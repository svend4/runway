# Решение: деньги — целые minor units

## ADR-002 Деньги — целые minor units

### Контекст

Прогноз остатка складывает сотни событий, а вердикт Q3 сравнивает минимум с буфером. Ошибка в одну копейку на границе меняет вердикт, а накопленная ошибка округления делает прогноз непроверяемым: «сумма движений обязана точно равняться изменению остатка». В JavaScript `19.99 * 100` даёт `1998.9999999999998`, а умножение суммы на курс или ставку легко выходит за 2⁵³ (произведение 2 000 000 000 000 × 9 250 уже около 1,85·10¹⁶). Реальные продукты решают это по-разному: YNAB хранит суммы в milliunits (1000 = единица валюты), Actual — в целых центах, в MCP-обёртках числа конвертируются на границе ([YNAB](../tools/ynab.md), [AI в финансах](../tools/ai-assistants-in-finance.md)); hledger работает с десятичными количествами по commodity и позволяет цену `@`/`@@` ([plain-text](../tools/plain-text-accounting.md)). Для крипты нужны 8 знаков (сатоши), для JPY — 0.

### Решение

1. Сумма — `amount_minor: int` (safe-integer, не более 2⁵³−1 по модулю) со знаком: доход положителен, расход отрицателен. Рядом всегда `currency` (ISO 4217 для фиата; для крипты код из реестра с `kind: crypto`) и `exponent` из реестра валют.
2. Деление и умножение денег — только через `round_div`, `mul_div`, `ceil_div`, `split_equal`, `split_largest_remainder`. `mul_div(a, num, den, mode)` внутри использует BigInt и возвращает safe-integer, иначе `fail(E_OVERFLOW)`.
3. Режим округления по умолчанию — `half_even` (банковское); правило может переопределить его (`half_up` — от нуля, `floor`, `ceil`). Округление выполняется **один раз** на производную величину (доход за период, налоговая аллокация, перевод по курсу).
4. Доли — только целые базисные пункты (`bp`, 10000 = 100 %) и промилле; проценты в деньгах не вводятся.
5. Дробление суммы: равные части (`split_equal` — лишние единицы получают первые части) и по весам (наибольшие остатки, ничья по индексу); итог всегда равен исходной сумме.
6. Float допустим только в статистике ([ADR-008](adr-008-uncertainty-scenarios-monte-carlo.md)) и интерфейсной анимации; деньги из float не выводятся. Любое нецелое число в записи журнала отклоняется валидатором.
7. Разбор и форматирование строк — собственные функции без `Intl`: `parse_minor`, `format_minor`.

### Рассмотренные альтернативы

| Вариант | Плюсы | Минусы | Почему не он |
|---|---|---|---|
| `Number` с плавающей точкой и округлением при выводе | просто | накопление ошибок, непредсказуемые ничьи, ломает хэши | нарушает инвариант сохранения суммы |
| Десятичная библиотека (класс decimal.js) | удобные операции | зависимость, скорость, непрозрачная сериализация | противоречит [ADR-001](adr-001-core-js-library.md) (нет зависимостей) |
| BigInt везде | нет предела | медленнее, не сериализуется в JSON без договорённости, тяжелее UI | BigInt нужен только при умножении |
| Фиксированные milliunits (1000 на единицу, как у YNAB) | единый масштаб | лишние знаки у фиата, не годится для крипты (8 знаков) | экспонента на валюту точнее |
| Рациональные числа | точные доли | сложнее сравнивать и хранить, рост знаменателей | достаточно целых и пары `num/den` для курса |

### Последствия

- Предел ±9,007·10¹⁵ минорных единиц (около 90 трлн евро) достаточен; крупные промежуточные произведения идут через BigInt.
- Курс хранится как `num/den` (см. [ADR-012](adr-012-fx-rate-policy.md)); конверсия между валютами с разной экспонентой учитывает обе экспоненты.
- Нужны тесты округления, дробления и переполнения: TST-16…19, TST-51 ([стратегия тестирования](../product/11-testing-strategy.md)); замок арифметики `arith.lock` фиксирует вывод ([ADR-014](adr-014-testing-approach.md)).
- Экспорт в hledger и CSV форматирует минорные единицы в десятичные строки без потерь.
- Любой «быстрый хак» с float ломает детерминизм — линтер ловит `Math.round(x * 100)` в `engine/`.

## Поправка v1.1

C-028: правило «округление один раз на производную величину» (п. 3) для дохода по часам выполняется буквально — **одно** `mul_div` на всю формулу с переработкой: `mul_div(rate_minor, min(m,T)·10000 + max(0, m−T)·mult_bp, 600000, rounding)`; прежняя схема из двух округлений (минуты, затем деньги) отменена, а `weighted_minutes` — справочная дробь. Ничья: `m = 2401`, `T = 2400`, ставка 3000, `mult_bp = 12500` → 120062,5 → `half_even` 120062, `half_up` 120063. Расхождение с учётом работодателя — до rate/120 minor на выплату; решение помечено для владельца в `_ops/canon-decisions.md`. Курс, введённый пользователем, хранится как введён, производные курсы — несократимая дробь (`gcd` в `money.mjs`, C-037).
