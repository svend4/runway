# Решение: язык и форма ядра

## ADR-001 Язык и форма ядра: общая JS-библиотека

### Контекст

Runway должен отвечать на Q1, Q2, Q3 одним и тем же числом везде: в интерфейсе, в Web Worker, в командной строке, в тестах и в ответе ассистента. Если клиент и сервер считают разным кодом, golden-тесты и проверяемый AI теряют смысл: проверять нечего. По словам автора Budget Guru в комментариях, его стек — React, Vite, Supabase, Vitest ([разбор](../tools/budget-guru.md)); где именно живёт расчёт, неизвестно, но политика описывает серверную функцию, получающую «снимок цифр». У [Actual Budget](../tools/actual-budget.md) API написан для Node.js, а браузерная сборка помечена экспериментальной и требует cross-origin isolation, то есть даже зрелый local-first продукт не получил одного кода везде. Разработчик один, поэтому цепочка поставки, скорость итераций и размер PWA (холодный старт офлайн) важны не меньше, чем скорость выполнения: расчёт на сотнях событий укладывается в миллисекунды (оценка в [предложении по движку](../ideas/proposal-engine.md), измерения будут в прототипе).

### Решение

1. Ядро — **JavaScript в виде ES-модулей с аннотациями JSDoc**, без зависимостей и без обязательной сборки: каталог `prototype/engine/` (карта модулей — [архитектура](../product/05-architecture.md)). `tsc --checkJs` запускается в CI как проверка типов, но не как шаг сборки.
2. Все функции ядра — **чистые**: в `engine/` запрещены `Date.now`, `new Date()`, `Math.random`, `fetch`, `fs`, `localStorage`, `process.env`; запрет проверяет линтер в CI. Всё внешнее приходит аргументами-портами: `as_of`, seed, `sha256`, курсы, данные хранилища.
3. Имена функций и полей — `snake_case` одинаково в псевдокоде вики и в JS-экспортах, чтобы псевдокод и код сверялись по имени.
4. Слои зависимостей направлены внутрь: `ui | mcp | cli → adapters (IndexedDB, fs) → ledger → engine`; движок про хранилище и сеть не знает.
5. Интерфейс — нативные элементы, Web Components и SVG; сторонних UI-зависимостей не более трёх, каждая — отдельным решением.
6. Тесты — встроенный `node --test`, собственный мини-генератор случайных журналов с seed.

### Рассмотренные альтернативы

| Вариант | Плюсы | Минусы | Почему не он |
|---|---|---|---|
| TypeScript с компиляцией | строгие типы, привычный инструментарий | шаг сборки, зависимость от компилятора и его версий, хуже воспроизводимость сборки | типизацию даёт `tsc --checkJs` без сборки; сумма экспертных оценок в матрице IDEA-82 — 97 против 86 (оценки субъективны) |
| Rust → WASM | детерминированная арифметика, скорость | тяжёлый инструментарий, холодный старт, труднее отлаживать одному | резерв на случай, если Монте-Карло (N = 2 000) не уложится в бюджет |
| Python-ядро на сервере | богатая числовая экосистема | нет офлайн и local-first, второй язык для клиента | противоречит [ADR-005](adr-005-local-first-optional-sync.md) |
| JS в браузере и отдельная серверная копия | привычная архитектура SaaS | расхождение расчётов, двойная поддержка | нарушает цель «одно число везде» |
| JS + JSDoc, один код везде | один код в Worker, Node, тестах; нулевая цепочка поставки | дисциплина проверок вместо типов | **выбрано** |

### Последствия

- Один модуль работает в Worker, в Node (CLI, MCP, CI) и в тестах; ассистент ([ADR-010](adr-010-ai-tools-and-number-verifier.md)) вызывает те же функции.
- Хэширование должно быть чистым: SHA-256 реализован внутри `ledger.mjs`, а не берётся из `node:crypto`.
- Форматирование чисел и дат через `Intl` допустимо только на границе интерфейса.
- Пересмотр: Rust → WASM, если замер Монте-Карло не укладывается в бюджет; SQLite-WASM — если событий больше 10⁵ ([ADR-004](adr-004-event-journal-projections.md)).
- Риск: JSDoc слабее типов — компенсируется `tsc --checkJs` и property-тестами ([ADR-014](adr-014-testing-approach.md)).

## Поправка v1.1

Арбитраж канона v1.1 (`_ops/canon-decisions.md`, C-095): слои из п. 4 («`ui | mcp | cli → adapters → ledger → engine`») — это **правило направления зависимостей**, а не отдельные каталоги. `ledger.mjs` и `io.mjs` лежат в `prototype/engine/` (`ledger` зависит только от `money`; `io` — от `ledger`, `dates`, `money`, `timeline`); `tsc --checkJs` (REQ-155) проверяет `engine/` целиком. Прочее решение без изменений.
