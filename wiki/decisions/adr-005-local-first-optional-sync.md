# Решение: local-first и опциональная синхронизация

## ADR-005 Local-first и опциональная зашифрованная синхронизация

### Контекст

Budget Guru хранит введённые данные в Supabase с изоляцией по строкам и административным доступом разработчика; сквозного шифрования, региона и бэкапов политика не упоминает ([политика](../../raw/03-budgetguru-privacy-terms.md), [разбор](../tools/budget-guru.md)), а часть цифр уходит провайдеру модели. RU-лендинг при этом заявляет, что «финансы остаются только вашими» — внутреннее противоречие. [Actual Budget](../tools/actual-budget.md) доказывает жизнеспособность local-first (файл на устройстве, опциональное E2E), но секреты банковской синхронизации лежат на сервере вне E2E. У [PocketSmith](../tools/pocketsmith.md) сквозного шифрования нет, self-host тоже. Красная команда указала на обратную сторону: для нетехнического релоканта потеря телефона или очистка хранилища браузера страшнее, чем админ-доступ; E2E без восстановления превращает забытый пароль в потерю облачной копии, а «доход от синхронизации» невозможно планировать, если синхронизации в v1 нет ([критика](../ideas/red-team-critique.md)). По сообщению WebKit, Safari может удалять скриптовое хранилище сайта после недель без визита (источник из предложения, в проекте не перепроверялся); поведение iOS нужно проверять на устройствах.

### Решение

1. **v1 — только устройство.** Хранилище `Store` — IndexedDB (журнал + снимки); при открытии `navigator.storage.persist()`; один писатель на все вкладки через Web Locks; сервис-воркер кэширует оболочку и версию движка. После первой загрузки оболочки основные сценарии v1 работают без сети (поправка v1.1, C-062).
2. **Файл-копия** — часть ядра: ручной экспорт и автозапись в выбранный пользователем файл там, где браузер позволяет; напоминание после N событий или 7 дней; баннер, если `persist()` не выдан или приложение не установлено как PWA.
3. **Аккаунтов, почты и серверной базы с открытыми суммами нет** ни в v1, ни позже.
4. **v2 — зашифрованный op-log**: журнал уже объединяется по `id` (G-Set), порядок `(hlc, device, seq)`; сегменты шифруются на устройстве (AES-GCM, подключ на сегмент из ключа, обёрнутого паролем через PBKDF2 с числом итераций по рекомендации OWASP, либо Argon2id как опция); ключ восстановления показывается при включении, но не блокирует работу; сервер хранит шифртекст, видны размер и время сегментов.
5. Конфликты поля решаются «последний по `(hlc, device)`», проигравшая правка остаётся в истории с меткой; CRDT-библиотека рассматривается только для совместного бюджета семьи.
6. Удаление: в v1 `eraseAll()` стирает хранилища и сервис-воркер на устройстве; облачное удаление через уничтожение ключевого заголовка — v2.
7. Честные границы пишутся в продукте: потеря устройства без копии — потеря данных; метаданные синхронизации видны серверу.

### Рассмотренные альтернативы

| Вариант | Плюсы | Минусы | Почему не он |
|---|---|---|---|
| A. Без синхронизации | максимальная приватность | потеря устройства — потеря данных | остаётся основой v1 вместе с B |
| B. Файл-копия | высокая приватность, просто | ручной ритуал | включено в v1 |
| C. Зашифрованный op-log на «тупом» хранилище | приватность, простая сервер-часть | потеря пароля — потеря облачной копии | v2, после появления пользователей |
| D. CRDT-библиотека через relay | слияние из коробки | зависимость, рост истории (не проверялось) | только для семьи |
| E. Серверная БД (как у Budget Guru) | восстановление пароля, простота | админ-доступ, зависимость от оператора | противоречит принципу «сервер — транспорт шифртекста» |

### Последствия

- В v1 нет дохода от синхронизации; модель дохода решается после v0 ([ADR-015](adr-015-v1-slice.md)).
- Поддержка проще: нет аккаунтов и восстановления доступа; зато нужен тщательный UX копий.
- Семейный режим откладывается до v2 и отдельного ADR (передача ключа общего хранилища не спроектирована).
- Облачный ассистент — отдельное согласие ([ADR-010](adr-010-ai-tools-and-number-verifier.md)); синхронизация его не включает.
- Подписанные релизы через сервис-воркер не делаем: проверку выполняет новый воркер, то есть возможно скомпрометированный код; вместо этого — воспроизводимая сборка и опубликованные хэши.

## Поправка v1.1

- C-062: единая формулировка офлайна — «после первой загрузки оболочки основные сценарии работают без сети»; «всегда офлайн» и «полностью работает без сети» не используются.
- C-081: в v1 локальное хранилище и файл-копия **не шифруются** — это остаточный риск, который описывается явно; защищённый паролем экспорт — v1.1 на том же коде WebCrypto, что и синхронизация v2. Ключи `kdf.iterations` и `kdf.wrap` зарезервированы в `vocab.json`, значения определяет ADR до v2; число итераций PBKDF2 (в том числе 600000 из предложения) — гипотеза, на 2026-10-04 не перепроверено. Функции `consent.revoke` и `redact` получают критерии приёмки внутри REQ-125 и REQ-138; ссылки на GDPR — ориентир, не юридический текст.
- C-072: порядок записей в v1 задаёт обязательное поле `seq`; `hlc` и `device_id` (п. 4) появляются в v2 с апкастером, который заполняет значения по умолчанию.
- C-096: напоминание о копии — `backup.remind_events` = 50 записей или `backup.remind_days` = 7 дней, что раньше (гипотезы в `vocab.json`).
