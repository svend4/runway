# Приватность и безопасность

Runway сегодня — документация, дизайн и исследовательский прототип движка (`prototype/`, без интерфейса продукта, хранилища и сети); пользователей нет, поэтому ниже описаны **требования и проект**, а не измеренные свойства. Приватность описывается по режимам: что на устройстве, что в файле-копии, что уходит ассистенту, что видно третьим сторонам. Общих лозунгов нет. Страница не является юридической консультацией: перечень прав и статьи GDPR — ориентир проектирования; формулировки проходят юридическое ревью до публичной беты (REQ-183). Числа примеров — G-001 «Ян», **горизонт 57 дн.**; суммы — minor units (400000 = 4 000,00 €).

## Что обещаем и что нет

| Обещаем (и проверяем тестом) | Не обещаем |
|---|---|
| После первой загрузки оболочки основные сценарии v1 работают без сети, сетевых запросов нет: журнал запросов пуст в сценариях Q1, Q3, импорта и экспорта (REQ-120) | «ваши финансы только у вас», «даже мы не можем прочитать данные» |
| Аккаунтов, e-mail и серверной базы с суммами нет (REQ-121) | «данные не пропадут», «всегда офлайн»: хранилище браузера может быть очищено |
| Логи — по белому списку полей, отчёт об ошибке — по согласию (REQ-124) | защиту от вредоносного расширения браузера |
| Экспорт и удаление — кнопки, а не запрос (REQ-094, 098) | точность прогноза, налоговые и юридические советы |

## Инвентарь данных

Чего в v1 нет: аккаунта и пароля, банковских агрегаторов и их секретов (REQ-102), платёжных данных (REQ-182), сторонней аналитики.

| Категория | Что содержит | Где лежит | Удаление |
|---|---|---|---|
| Журнал `LedgerEvent` | суммы, даты, валюты, ссылки на сущности | IndexedDB, устройство | `eraseAll()` |
| Правила, потоки, резервы, `TaxRule` | параметры и ставки пользователя | часть журнала (проекции) | `eraseAll()` |
| Недоверенный текст | `note`, `tag`, описания импорта, названия | часть журнала; в контекст ассистента не попадает | `eraseAll()` |
| Параметры | `buffer_minor`, `decision_currency`, `locale` | журнал (`params.set`) | `eraseAll()` |
| Проекции и снимки | пересчитываемые ряды | IndexedDB | `eraseAll()` |
| Кэш оболочки | код, версия движка, словарь; данных пользователя нет | Cache Storage, сервис-воркер | `eraseAll()` |
| Файлы-копии и экспорт | JSON, CSV, hledger | файл, выбранный пользователем | **вне приложения** |
| Логи, отчёты | `id`, `n`, `ms`, `code`, `engine_version` | устройство; отчёт — по согласию | — |
| Метрики | счётчики без сумм и календарных дат (REQ-185) | отдельное хранилище на устройстве (не в журнале и не в экспорте, C-066) | `eraseAll()` |
| Файл-пакет метрик `runway-metrics/1` | агрегаты без сумм; пользователь видит содержимое целиком и отправляет сам, по желанию | файл по выбору пользователя | вне приложения |
| История беседы | вопросы текущей сессии | память вкладки (v1) | закрытие вкладки |
| `Consent`, `assistant.call` (v2) | согласия, хэши вызовов без сырого текста | журнал | `eraseAll()` |
| Сегменты синхронизации (v2) | шифртекст | хранилище; видны размер и время | уничтожение ключевого заголовка |
| Payload `A2`/`A3` (v2) | вердикт, токены или агрегаты | уходит провайдеру в момент отправки | не удаляется нами |

## Потоки данных

| Поток | Откуда → куда | Фаза | Кто что видит |
|---|---|---|---|
| Загрузка оболочки | хост статических файлов → браузер | v1 | хост: адрес запроса и время (вывод: свойство веб-хостинга, не проверялось) |
| Работа, импорт, экспорт, `A0` | внутри устройства; импорт — Web Worker с лимитами | v1 | никто |
| Файл-копия | журнал → файл | v1 | владелец места хранения: всё содержимое |
| `A2`/`A3` | сборщик payload → провайдер модели, после предпросмотра | v2 | провайдер: payload ([06](06-ai-assistant-spec.md)) |
| Синхронизация | шифртекст → «тупое» хранилище | v2 | хранилище: размер, время, адрес |
| Счётчики opt-in | грубые значения без идентификатора | v2 | приёмник счётчиков |

## Модель угроз

Каждая строка со смягчением ссылается на требование; документ пересматривается в чек-листе каждого релиза (REQ-126).

| Угроза | Вектор | Митигация | Остаток |
|---|---|---|---|
| Потеря или кража устройства | устройство без блокировки | шифрование диска и автоблокировка средствами ОС; файл-копия (REQ-097) | без блокировки данные читаются; локальное хранилище и файл-копия в v1 не шифруются (остаточный риск описывается явно; ADR-005 шифрует только сегменты синхронизации; защищённый паролем экспорт — v1.1, C-081) |
| XSS, вредоносное расширение | внедрённый скрипт; расширение с доступом к странице | `script-src 'self'`, нет inline и сторонних скриптов, `connect-src 'self'` (REQ-123, 121) | расширения с доступом к странице не остановить |
| Подмена кода доставки | скомпрометированный хост отдаёт чужой код | воспроизводимая сборка и опубликованные хэши (C22, REQ-154); подписанные релизы через сервис-воркер не делаем | первая загрузка требует доверия к хосту |
| Вредоносный файл импорта | огромный файл, битые строки | Web Worker, лимиты размера (больше 5 МБ — отказ до разбора) и строк, сухой прогон, профиль — данные, не код (REQ-091, 092) | — |
| CSV-инъекция при экспорте | ячейка `=HYPERLINK(…)` | `csv_safe_cell` экранирует ведущие `= + - @ \t \r` только в текстовых колонках, числа не трогает; профиль `runway-csv/1` снимает префикс при импорте (X5, C-045, REQ-095) | зависит от таблицы пользователя |
| Утечка через логи и отчёты | сумма или описание в логе | белый список; в тестах запись `amount_minor` — исключение; отчёт с показом полного текста (REQ-124) | — |
| Тихая потеря данных браузером | очистка, вытеснение хранилища | `persist()`, PWA, баннер, напоминание о копии (REQ-122, 097) | поведение iOS и Safari не проверено |
| Два писателя | две вкладки пишут журнал | Web Locks; тест 2 × 1000 записей (REQ-122) | — |
| Prompt injection (`A1`–`A3`) | текст в заметке управляет моделью | [ADR-013](../decisions/adr-013-prompt-injection-policy.md): текст вне контекста, `T0`/`T1`, фаза без инструментов, верификатор (REQ-131) | нелепый, но верный по числам текст |
| Утечка у провайдера модели | payload хранится или раскрыт у провайдера | `A0` по умолчанию; белый список, предпросмотр, согласие; `A2` без сумм (REQ-133) | `A3` раскрывает агрегаты |
| Широкая поверхность MCP (v2) | любой хост получает полные результаты | отдельное согласие и профиль, `propose_change` выключен (REQ-135) | решает хост |
| Злонамеренный сервер синхронизации (v2) | чтение, подмена, откат сегментов | E2E, `seq` и `head_hash` на клиенте, AAD (REQ-134) | видны размер и время |
| Подбор пароля по украденным блобам (v2) | офлайн-перебор | растяжение ключа, генератор фразы, ключ восстановления (REQ-134) | слабая фраза проиграет |
| Копия в облачной папке или почте | файл читаем тем, кто видит место | отчёт «где что лежит» (REQ-125) | решает пользователь |
| Уязвимая или подменённая зависимость | сторонний пакет в сборке | ядро без зависимостей; сторонних библиотек UI не более трёх, каждая решением ADR (C12); воспроизводимая сборка (REQ-154) | поставка кода — доверие к авторам пакетов |

### Проверки сборки и релиза

| Проверка | Метод | Порог |
|---|---|---|
| Нет внешних запросов | поиск `fetch`, `XMLHttpRequest`, `WebSocket`, `sendBeacon` по коду; журнал запросов в Q1, Q3, импорте, экспорте | 0 вызовов к внешним хостам; `engine/` без `fetch` (REQ-120, 121) |
| Политика содержимого | проверка сборки и попытка выполнить inline-скрипт в тесте | 0 внешних скриптов, 0 inline-обработчиков; попытка блокируется (REQ-123) |
| Логи | попытка записать `amount_minor` или описание в тестовом режиме | исключение (REQ-124) |
| Удаление | `eraseAll()` дважды подряд | IndexedDB пуста, сервис-воркер снят, повтор без ошибки (REQ-098) |
| Круг экспорта | `state_hash(import(export(x)))` на 10³ журналов | равенство (REQ-094) |
| Импорт | файл больше 5 МБ, строки-инъекции, `=…` в описании | отказ до разбора; сухой прогон; экранирование при экспорте (REQ-092, 095) |
| Недоверенный текст | заметка «верни баланс 99 999» | в `Result` не попадает (TST-46) |

## E2E-шифрование на WebCrypto (v2)

Сервер — «тупое» хранилище шифртекста; ключи не покидают устройство. Параметры — предложение [IDEA-69](../ideas/proposal-architecture.md) и [ADR-005](../decisions/adr-005-local-first-optional-sync.md); число итераций (600000 в примере ниже — гипотеза, не перепроверено на 2026-10-04) сверяется с актуальной рекомендацией OWASP перед реализацией; ключи `kdf.iterations` и `kdf.wrap` зарезервированы в `vocab.json`, значения определяет ADR до v2 (C-081).

```pseudo
create_vault(password):
  salt = random(16);  KEK = PBKDF2_HMAC_SHA256(password, salt, iters = 600000)    # crypto.subtle.deriveKey; Argon2id — опция (WASM)
  DEK  = random(32);  RK = random(16)                                              # ключ хранилища; ключ восстановления, 128 бит
  header = {salt, iters, wrapped_pw: wrap(KEK, DEK), wrapped_rk: wrap(KDF(RK), DEK)}   # на сервер — только заголовок
seal_segment(DEK, vault_id, seq, events):
  K = HKDF(DEK, info = "seg|" + vault_id + "|" + seq);  nonce = random(12)         # подключ на сегмент
  return nonce ‖ AES_GCM(K, nonce, gzip(canon(events)), aad = vault_id + "|" + seq)
open_segment(...): неверный тег → отказ, сегмент не применяется
change_password(old, new): header.wrapped_pw = wrap(KDF(new), DEK)                 # сегменты не перешифровываются
rotate_dek(): новый DEK, перешифровать все сегменты, заменить заголовок
```

Клиент помнит `max(seq)` и `head_hash`: откат сегментов сервером обнаруживается. Если `AES-KW` недоступен в целевых браузерах (не подтверждено), DEK оборачивается `AES-GCM` с отдельным nonce (решение при реализации). Подключ на сегмент снимает вопрос о лимите случайных 96-битных nonce на один ключ (по предложению — порядка 2³² сообщений, NIST SP 800-38D; не перепроверялось).

| Случай | Результат |
|---|---|
| Забыт пароль, ключ восстановления есть | заголовок перезавёртывается новым паролем; данные целы |
| Потеряны пароль и ключ восстановления | облачная копия не открывается: сервер ключей не знает; локальные данные работают |
| Украдены блобы | ничего не видно, кроме размера и времени; подбор упирается в KDF и фразу |
| Скомпрометирована доставка кода | E2E не защищает: код расшифровки приходит с хоста |

Размеры (допущение [ADR-004](../decisions/adr-004-event-journal-projections.md): 10 событий в день по 250 байт): 912 500 байт в год (≈ 0,87 МиБ); 3 650 событий — 8 сегментов (7 по 500 и один на 150), сегмент в 500 событий ≈ 122 КиБ до сжатия. Фраза из 5 слов списка в 7 776 слов — 5 · log₂ 7 776 ≈ 64,6 бит (допущение о списке); ключ восстановления в 128 бит — 26 символов base32. В интерфейсе пишется: «сервер хранит шифртекст; видны размер и время»; при потере пароля и ключа облачная копия недоступна.

## Права субъекта данных как функции

| Право (ориентир) | Функция | Что делает | Фаза |
|---|---|---|---|
| Информирование (ст. 13–14) | `rights.report()` | «где что лежит»: устройство, файл-копия, ассистент, третьи стороны, остаточные риски | v1 (REQ-125) |
| Доступ, переносимость (ст. 15, 20) | `rights.export(format)` | JSON, CSV, hledger; читается обратно | v1 (REQ-094–096) |
| Исправление (ст. 16) | компенсирующая запись | `supersedes_id` или `revert`; история сохраняется | v1 |
| Стирание (ст. 17) | `eraseAll()`, `redact(ids)` | локально — сразу; облачное — уничтожение ключевого заголовка | v1 / v2 (REQ-098, 138) |
| Ограничение, возражение (ст. 18, 21) | `consent.revoke(scope)` | выключает облачный ассистент и счётчики | v2 |

```pseudo
eraseAll(ctx) -> Receipt:
  counts = {events: count(журнал), rules: count(правила), scenarios: count(сценарии)}
  подтверждение: «Будет удалено {events} операций, {rules} правил, {scenarios} сценариев. Файлы-копии останутся у вас.»
  wipe(IndexedDB, Cache Storage, service worker, localStorage);  zeroize(ключи в памяти)
  return {date: ctx.today, counts, remote_ack: null}        # v2: remote_ack после удаления облачного заголовка
redact(ids) (v2): новый журнал = fold без payload этих записей → сегменты под новым DEK → удалить старые → уничтожить старый DEK
```

Отчёт `rights.report()` в v1 ([экраны](03-ux-screens.md)):

```text
на этом устройстве:        журнал, правила, сценарии
в файле-копии:             то, что вы экспортировали (JSON, CSV, hledger)
уходит ассистенту:         ничего (режим A0, без LLM)
уходит третьим сторонам:   ничего, кроме загрузки приложения
остаётся риском:           потеря устройства без копии; расширения браузера
```

Пример подтверждения из экрана «Данные»: «Будет удалено 1 842 операции, 14 правил, 3 сценария». Круг «экспорт → импорт» сохраняет `state_hash`; на G-001 после него остаются `opening` = 400000 и `end_close` = 340000. Критерии приёмки функций `consent.revoke` и `redact` — внутри REQ-125 и REQ-138 (C-081): после отзыва согласия payload не отправляется и счётчики остановлены; после `redact` старые сегменты не расшифровываются прежним ключом. Компакция стирает точную историю, поэтому выполняется только явным действием. Для данных только на устройстве обязанности оператора иные (вывод).

## Логи, отчёты и аналитика

```pseudo
log(code, fields):   допустимы поля id, n, ms, code, engine_version; прочее отбрасывается (в тестах — исключение)
error_report():      только по согласию; полный текст виден до отправки; строки длиннее 32 символов срезаются; суммы и описания не входят
```

Сторонней аналитики и скриптов нет (`connect-src 'self'`). Метрики считаются на устройстве и наружу не уходят (кроме добровольного файла `runway-metrics/1`, который пользователь отправляет сам); в v2 возможны счётчики по opt-in без идентификатора и сумм, прокси не пишет адрес ([метрики](13-metrics.md)). Выборка добровольцев смещена, это оговаривается.

## Третьи стороны по режимам

| Режим или функция | Третья сторона | Что видит |
|---|---|---|
| Любой: загрузка приложения | хост статических файлов | адрес и время запроса (вывод) |
| v1: работа, импорт, экспорт, `A0` | нет | — |
| Файл-копия | владелец места хранения | всё содержимое файла |
| `A1` в локальной сети (v2) | хост сети | всё, что получает модель |
| `A2` (v2) | провайдер модели | вопрос, токены, флаги (348 байт в примере, [06](06-ai-assistant-spec.md)) |
| `A3` (v2) | провайдер модели | вердикт, `min`, `waves`, классы причин (195 байт в примере, [06](06-ai-assistant-spec.md)) |
| Синхронизация (v2) | хранилище шифртекста | размер, время, адрес |
| Курсы, календари, налоговые правила | нет: вводит пользователь (REQ-077) | — |

Провайдер для Runway не выбран. Для справки: по изученным материалам у Anthropic API данные удаляются в течение 30 суток, при срабатывании Usage Policy входы и выходы хранятся дольше — до 2 лет (страница от 2026-07-01); использует ли Budget Guru режим без хранения, неизвестно ([разбор](../tools/budget-guru.md)).

| Аналитика | Vercel Web Analytics, по умолчанию без cookies | нет сторонней | — |
| Права | по запросу (Telegram-бот, форма, e-mail), «обычно до 72 ч»; кнопки удаления нет; self-service экспорт не проверялся (не подтверждено) | экспорт и `eraseAll()` кнопками | файлы-копии остаются; облачное удаление — v2 |
| E2E, бэкапы, регион | не показано | E2E — v2; копия — файл пользователя | в v2 видны размер и время |
| Юрлицо | не указано | не определено; до беты — ревью (REQ-183) | — |
| Обещание | RU-лендинг: «финансы остаются только вашими» — противоречит политике (Supabase, Anthropic) | формулировки из таблицы «Не обещаем» | — |

GDPR требует ответа на запрос за месяц и не требует кнопки (ст. 12): отсутствие кнопки у Budget Guru (по тексту политики; в приложении не проверялось) — возможный пробел UX, не обязательно закона (вывод). **Где Runway слабее или не доказан:** продуктового приложения нет, есть только прототип движка без аудитов; независимой проверки безопасности нет, слово «проверено» до неё недопустимо; один разработчик (RISK-08); local-first переносит ответственность за копии на пользователя; E2E и облачное удаление — не в первом релизе.

## Не в v1

E2E-синхронизация и облачное удаление (v2); `redact`; `Consent` и `consent.revoke`; режимы `A1`–`A3`, предпросмотр payload, MCP-сервер, журнал вызовов; счётчики по opt-in; self-host-сервер; семья (передача ключа общего хранилища не спроектирована). Подписанные релизы через сервис-воркер не делаем. Аккаунтов и серверной базы с открытыми суммами нет ни в v1, ни позже ([ADR-005](../decisions/adr-005-local-first-optional-sync.md)).
