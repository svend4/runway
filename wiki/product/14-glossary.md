# Глоссарий Runway

Словарь нормативный: страницы вики, псевдокод и прототип используют термины ровно в этом значении. Формулы и значения по умолчанию заданы в каноническом ТЗ проекта (`_ops/design-brief.md`) и решениях [ADR-006](../decisions/adr-006-forecast-semantics.md), [ADR-016](../decisions/adr-016-reserves-and-safe-to-spend.md). Деньги — целые `amount_minor` с кодом валюты ([ADR-002](../decisions/adr-002-money-minor-units.md)), даты — календарные ([ADR-003](../decisions/adr-003-civil-dates.md)). Налоговые термины описывают арифметику по правилам, которые вводит пользователь; это не консультация. О Budget Guru известны только заявления лендинга, политики и условий: вход в приложение не выполнялся, функции не проверялись, аккаунтов нет ([страница](../tools/budget-guru.md)). Глоссарий приведён к канону v1.1 (решения C-001…C-098).

Числа в примерах относятся к сквозному примеру G-001 «Ян» (аренда 25-го, налоговый конверт 20 %, дорожка 300,00 €, `as_of` 2026-10-04): буфер 500,00 €, `plan`-минимум денег 2 055,00 €, минимум «если хуже» 1 830,00 €. Все числа G-001 воспроизводятся только при явном `horizon_days = 57` (горизонт 57 дн., до 2026-11-30); при горизонте по умолчанию (180) числа другие (X2).

| Термин | Код / EN | Определение | Страница-владелец |
|---|---|---|---|
| Дата вычисления | `as_of` | Явный параметр запроса: «сегодня» берётся с устройства и фиксируется в `inputs_hash`; движок не читает часы. Планы на эту дату ещё «впереди», факты уже в остатке | [ADR-003](../decisions/adr-003-civil-dates.md) |
| Календарная дата | civil date, `EpochDay` | Гражданская дата без часового пояса: в движке целое число дней с 1970-01-01, на диске и в тексте `YYYY-MM-DD`. Время есть только в `recorded_at` для аудита | [ADR-003](../decisions/adr-003-civil-dates.md) |
| Горизонт | `horizon_end`, `horizon_days` | Последний день, до которого развёртываются вхождения; по умолчанию 180 дней (в примере G-001 — 57 дн.). За горизонтом ответ — «в горизонте нет» (`outside_horizon`) | [Прогноз денежного потока](../concepts/cash-flow-forecast.md) |
| Прогноз денежного потока | cash-flow forecast | Траектория остатка по дням от `as_of` до горизонта, построенная из фактов, планов и гипотез одним движком; отвечает на Q1, Q2, Q3 | [Прогноз денежного потока](../concepts/cash-flow-forecast.md) |
| Остаток на конец дня | `close` | Остаток после всех событий дня; ряд для отображения | [ALG-02](../algorithms/alg-02-timeline-projection.md) |
| Минимум дня | `trough` | Остаток после расходов дня, но до его доходов («расходы раньше доходов»); физический минимум денег внутри дня, используется во всех режимах | [ALG-02](../algorithms/alg-02-timeline-projection.md) |
| Узкая точка | narrowest point | Дата и сумма наименьшего `trough` на отрезке; при равенстве побеждает ранняя дата. Для вердиктов используется «свободная узкая точка» `narrowest_free` — то же по ряду `free`; слово без уточнения означает `trough` | [ALG-02](../algorithms/alg-02-timeline-projection.md) |
| Хватит ли к дате | Q1, `Q1Answer` | Вопрос о пути, а не о точке: минимум `trough` на `[as_of, D]` и его дата, `ok_cash` (минимум не ниже нуля), `ok_buffer` (не ниже буфера), первая дата пробоя нуля и буфера, `need = max(0, B − минимум)` — «не хватает до буфера (деньги на счетах)». Дата за горизонтом — `beyond_horizon` | [Прогноз денежного потока](../concepts/cash-flow-forecast.md) |
| Дата кассового разрыва | `runway_with`, `runway_without` | Первый день на всём горизонте, когда `trough < 0` (деньги на счетах не покрывают расходы дня): с доходами и без них; нет такого дня — «за горизонтом». Считается по `trough`, не по `close` | [Прогноз денежного потока](../concepts/cash-flow-forecast.md) |
| Буфер | `buffer_minor`, `B` | Число пользователя в валюте решения: запас, ниже которого минимум считается нарушением. Показывается в каждом ответе. Не задан (`null`) — Q1 и волны считают `B = 0` с `W_BUFFER_UNSET`, а Q3 и «можно потратить» не отвечают (причина `no_buffer`); явный `0` — «задан» | [ADR-006](../decisions/adr-006-forecast-semantics.md) |
| Подсказка буфера | `buffer_hint` | Семь дней средних расходов по факту последних 90 дней: только исходящие `posted`, без переводов между своими счетами, налоговых платежей, аллокаций в резервы, ног обмена и пометки `exceptional` (X6); предлагается пользователю, но не пересчитывается из будущего | [ADR-006](../decisions/adr-006-forecast-semantics.md) |
| Режим расчёта | mode | Пакет параметров обработки дат: `plan`, `worse`, в v2 `expected`. Не сценарий и не набор правок данных | [Неопределённость и сценарии](../concepts/uncertainty-and-scenarios.md) |
| По плану | `plan` | Даты и суммы как введены; просроченное вхождение считается на `as_of` | [ADR-006](../decisions/adr-006-forecast-semantics.md) |
| Если хуже (консервативный) | `worse` | Каждое ожидаемое поступление сдвинуто на `worse.income_delay_days` (по умолчанию 14); расходы и суммы не меняются. Сдвиг режима накапливается со сдвигом сценария (7 + 14 = 21 день). Старое имя `conservative` — синоним | [ADR-006](../decisions/adr-006-forecast-semantics.md) |
| Ожидаемый | `expected` (v2) | Даты сдвинуты на медианный лаг потока по его истории; включается при не менее 10 наблюдений | [ALG-13](../algorithms/alg-13-plan-vs-actual-calibration.md) |
| Сценарий | scenario | Именованный набор правок данных без копирования: сдвиг дохода, покупка, добавление или удаление платежа. Гипотезы сценария не пишутся в журнал фактов. Сначала сценарий правит данные, затем режим добавляет сдвиг; предпросмотр правки правила («а что если 22 %») — не операция сценария | [Неопределённость и сценарии](../concepts/uncertainty-and-scenarios.md) |
| Плановая дата | `plan_date` | Служебное поле события: дата после правок сценария и до режима, без зажима `max(·, as_of)`; `base(e) = max(plan_date, as_of)`; в журнал не пишется | [Неопределённость и сценарии](../concepts/uncertainty-and-scenarios.md) |
| Готовность данных | readiness | Счёт от 0 до 4: есть счёт, есть три обязательства или волна, есть доход в ближайшие 45 дней, задана оценка повседневных трат. Прогноз виден от 3, вердикт Q3 — при 4 | [Прогноз денежного потока](../concepts/cash-flow-forecast.md) |

## Факт, план, гипотеза и сопоставление

| Термин | Код / EN | Определение | Страница-владелец |
|---|---|---|---|
| Факт | `posted` | Подтверждённое движение денег; неизменяем, исправляется только компенсирующей записью. Дата не позже `as_of` | [ADR-004](../decisions/adr-004-event-journal-projections.md) |
| План | `planned` | Вхождения правил (виртуальные, не хранятся), разовые плановые записи и доходы потока часов | [ADR-004](../decisions/adr-004-event-journal-projections.md) |
| Гипотеза | `hypothetical` | Событие сценария («а что если»); существует только внутри сценария | [ADR-004](../decisions/adr-004-event-journal-projections.md) |
| Вхождение | occurrence | Конкретная дата платежа, порождённая правилом повторения; имеет стабильный ключ `occ_key` | [Правила повторения](../concepts/recurrence-rules.md) |
| Статус вхождения | occurrence status | `expected`, `matched`, `overdue`, `skipped`, `cancelled`; перенос — не статус, а переопределение даты | [ALG-13](../algorithms/alg-13-plan-vs-actual-calibration.md) |
| Просрочено | `overdue` | План, у которого дата плюс допуск (`grace_days`: доход 3 дня, расход 0) раньше `as_of`, а факта нет. Считается на `as_of` (плюс задержка в `worse` для дохода) | [ALG-13](../algorithms/alg-13-plan-vs-actual-calibration.md) |
| Сопоставление план↔факт | matching, reconciliation | Привязка факта к плану в окне 3 дня и допуске суммы 5 %; автоматически только при единственном кандидате, иначе очередь подтверждения | [ALG-13](../algorithms/alg-13-plan-vs-actual-calibration.md) |
| Возможный двойник | possible double | Факт с отклонением суммы до двух допусков: план не снимается, оба учитываются до решения пользователя | [ALG-13](../algorithms/alg-13-plan-vs-actual-calibration.md) |
| Якорь остатка | `Anchor` | Подтверждённый остаток счёта на дату; проекция стартует от последнего якоря | [ALG-13](../algorithms/alg-13-plan-vs-actual-calibration.md) |
| Дрейф | drift | Разница между якорем и суммой проведённых операций; показывается, а не скрывается. Не путать с «дрейфом даты» (потеря 31-го числа при последовательном прибавлении месяцев; см. «Конец месяца») | [ALG-13](../algorithms/alg-13-plan-vs-actual-calibration.md) |
| Свежесть данных | staleness | Возраст последнего якоря по самому несвежему operating-счёту: более 7 дней — плашка с оценкой неучтённого, более 21 дня — вердикт Q3 заменяется «данных мало»; у счёта без якоря возраст неизвестен — уровень `block`, причина `no_anchor` | [ALG-13](../algorithms/alg-13-plan-vs-actual-calibration.md) |
| Гейт Q3 | gate, `insufficient_data` | Общий для Q3 и «можно потратить»: нет ответа, если готовность < 4, уровень свежести `block`, не задан буфер или есть правило в статусе `disabled` (причины `readiness`, `stale`/`no_anchor`, `no_buffer`, `rule_disabled`). Q1 и волны гейтом не блокируются | [ALG-04](../algorithms/alg-04-can-i-afford.md) |

## Волны платежей

| Термин | Код / EN | Определение | Страница-владелец |

| Порог значимости | `wave.threshold_minor`, `θ` | Обязательства ниже порога в волны не входят; по умолчанию `θ = max(30·10^exp, round_div(Σ исходящих posted за 90 дн., 300))` в валюте решения, без истории — `30·10^exp` (X1; в G-001 θ = 3000) | [ALG-03](../algorithms/alg-03-payment-waves-detection.md) |
| Нужно к волне | `need_w` | Пиковая просадка в окне волны плюс буфер: сколько денег нужно на начало волны, чтобы пережить её и дожить до следующего поступления | [ALG-03](../algorithms/alg-03-payment-waves-detection.md) |
| Покрытие волны | `coverage_pm` | Деньги на начало волны, делённые на `need_w`, в промилле (целая часть; при `cash_w < 0` — отрицательное целое) | [ALG-03](../algorithms/alg-03-payment-waves-detection.md) |

| Не хватает до буфера (с учётом резервов) | `short_to_buffer` | `B − минимум free`; ряд — `free`. В G-001-low 136500 / 159000, в G-001-gap 256500 / 279000 (по плану / если хуже) | [ALG-11](../algorithms/alg-11-safe-to-spend.md) |

| Перевод | `transfer` | Реальное движение денег между счетами из двух ног с нулевой суммой; в отличие от резерва меняет остатки счетов | [ADR-016](../decisions/adr-016-reserves-and-safe-to-spend.md) |
