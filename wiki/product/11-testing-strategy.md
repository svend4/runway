# Стратегия тестирования Runway

Страница определяет тест-кейсы TST-01…TST-60 и порядок их запуска; подход — [ADR-014](../decisions/adr-014-testing-approach.md). Других идентификаторов TST нет. Числа — сквозной пример G-001 «Ян» и независимые векторы канона. **Ключи `G-001.*` воспроизводятся только при горизонте 57 дн.** (`horizon_end` 2026-11-30, N = 58, буфер 500,00 €): при горизонте 180 в ряд попадают события 2026-12-07 и 12-25, и числа другие — это не ошибка. Деньги — minor units (`205500` = 2 055,00 €). Налоговые числа — арифметика по введённым правилам, не консультация. Прототип есть ([`prototype/`](15-prototype-guide.md); сквозной прогон 2026-11-09 — 202 файла, 3551 тест): ожидаемые значения в тестах переписаны из канона дословно, а не взяты из вывода движка; ключи G-001 пересчитаны независимым оракулом (день за днём, целые числа и BigInt, события вписаны вручную), числа совпали с каноном и с движком (неточность найдена лишь в пояснении к таблице §9.4 о «пропущенных днях»: сохраняется только `close`). Что реально запускается и что каждая часть ловит — раздел «Тестовая сеть прототипа», статус каждого TST — раздел «Статус TST в прототипе».

Golden на синтетике проверяет стабильность, а не истинность, поэтому над ним стоят оракул, hledger и backtest. Не делаем: сторонняя property-библиотека ([ADR-001](../decisions/adr-001-core-js-library.md)), снимки интерфейса как основа.

## Генератор журналов

Собственный мини-генератор без `Math.random`; упавший случай печатает seed и сжимается.

```pseudo
gen_journal(seed, size):
  rules  = [freq ∈ {D,W,M,Y}, by_monthday ∈ {1..31, −1}, month_end, weekend]
  events = [amount_minor ∈ {0, ±1, ±10^k, ±(2^53−1)}, date ∈ 1970..2100]
  return { journal, rules, params, as_of, horizon_end }

check_property(prop, n, seed0):
  for i in 0 ..< n:
    case = gen_journal(seed0 + i, size_for(i))
    if not prop(case): return shrink(prop, case)    # убирать половину событий, пока prop ложно
```

В прототипе генератор — `tests/journal_gen.mjs`: прежний `random_journal`; `case_seed(base, i)` — seed i-го журнала серии (mulberry32, без `Math.random` и часов); `gen_case(seed)` — валидный журнал со счетами, якорями, фактами, правилами, потоком часов, разовыми планами, налоговым конвертом, накоплениями, заменами (`supersedes_id`), откатами и откатами откатов, плюс рабочая область и запрос; `with_mirror_facts` — «зеркальные» факты для проверки сопоставления; `gen_small(seed, kind)` — малые журналы (пустой, одно событие, дубли дат, крайние значения); `EDGE_VALUES` — 0, ±1, ±2, ±(2⁵³−1). Упавший случай воспроизводится по seed; сжатия случая (`shrink` из псевдокода выше) в прототипе нет.

Волна — день 10. `plan`: окно 10…29, `cash_w` 1500, min `trough` 200 · день 25, `R_w` 1300, `need_w` 1600, `gap_w` 100. `worse`: следующий приход — A (день 17), окно 10…16, `cash_w` 1000, min `trough` 600 · день 10, `R_w` 400, `need_w` 700, `gap_w` 0 — то есть `worse` **лучше** `plan`, хотя `trough_worse[i] ≤ trough_plan[i]` в каждый день. Безусловны только свойства рядов (`trough`, `free`) и `S_max` (TST-35).

### TST-07 G-001: «почему» — цепочка и контрфакты

ALG-02 · REQ-030, 057, 104. Режим `worse`: узкая точка 183000 · 11-14, пик `close` 400000 · 10-04, просадка 217000. Цепочка (стоп при накопленной доле ≥ 9000 bp): аренда 90000 — 4147 bp; продукты 60000 — 2765 (накоплено 6912); налог 50000 — 2304 (накоплено 9217). Знаменатель долей — `out_total` = сумма расходов окна `[w0, t]` = 217000 (приходов в окне нет: `inflow_offset` = 0; в общем случае `peak − min = out_total − inflow_offset`); `share_bp = round_div(10000·сумма, out_total)` (`half_even`). Накопленная доля считается от накопленной суммы (`round_div(10000·200000, 217000)` = 9217, а не 9216 из суммы округлённых долей; расхождение ≤ 1 bp допустимо): тест фиксирует §9.8 и C-007. Группы цепочки в `Result` инструмента — идентификаторы (`R-RENT`, `R-GROC`, `P-TAX1`) и `cause_class`, не `tag` (C-097). Контрфакты (новый min `trough`): без аренды 273000 · 11-14; без продуктов 243000 · 11-09; без налога 233000 · 11-14; доход вовремя 205500 · 10-31.

### TST-12 Сдвиг выходных и `exdates`

ALG-01 · REQ-008–009. 2026-10-25 (воскресенье): `next` → 10-26, `prev` → 10-23, `keep` → 10-25, `skip` → `null`; 11-25 (среда) без сдвига. `exdates = [2026-10-17]` у `R-GROC`: суббота пропущена — 7 вхождений вместо 8. ### TST-15 Даты: `days_from_civil` ↔ `civil_from_days`, `dow`

### TST-17 Дробление: `split_equal`, наибольшие остатки

ADR-002 · REQ-004. `split_equal(110000, 6)` = [18334, 18334, 18333, 18333, 18333, 18333]; `split_equal(30000, 7)` = [4286 ×5, 4285 ×2]; `split_largest_remainder(37500, [12000, 4200, 21313])` = [11996, 4198, 21306]; сумма частей всегда равна исходной.

### TST-18 `mul_div` на BigInt выше 2⁵³

ADR-002 · REQ-002. `mul_div(3, 2999999999999999, 2, half_even)` = 4499999999999998 (наивное `Math.round` даёт …999); `mul_div(5, 1999999999999999, 4)` = 2499999999999999 (произведение 9999999999999995 > 2⁵³ — только через BigInt); `mul_div(9007199254740991, 2, 1)` → `fail(E_OVERFLOW)`.

### TST-21 Sinking: отпуск с догоном и пул

### TST-36 Свойство: аддитивность дельта-сценариев

ALG-02 · REQ-049–050, 171. ### TST-38 Свойство: round-trip экспорта (`state_hash`)

ALG-14 · REQ-012, 016, 094–095, 097–098, 122, 171, 187. `state_hash(import_json(export_json(s))) = state_hash(s)`, где `state_hash(state) = hex(sha256(canon(state)))`, а `state = reduce(effective_events(journal))` — свёртка, не лог; `recorded_at` в неё не входит (C-071); `canon` — детерминированный JSON (ключи по кодовым точкам, без пробелов, только safe-integer, строки NFC, множества отсортированы), поэтому round-trip воспроизводим двумя реализациями; `seq` обязателен (C-072). ### TST-39 Свойство: `S_max(as_of) = STS(horizon_end)`; без резервов `free = trough`

ALG-04, ALG-11 · REQ-041–042, 045, 171. G-001: 43500 = 43500 (`plan`), 21000 = 21000 (`worse`). Без `RES-TAX` и `RES-INS` `free = trough`: `S_max` 155500 / 133000, дорожка 300,00 € → `OK` (пересчёт по D-08, D-11; семантика v0, где резервов нет; при этом показывается `W_NO_RESERVES` и подпись «без учёта резервов», C-065).

Защитный признак `baseline_below_buffer_m = min_i free_m[i] < B` (C-015): при нём `S_max_m(D) = 0`, `earliest_m = null`, вердикт `OK` невозможен при `m = worse`, а при `m = plan` не выше `TIGHT`. Синтетика: `free = [100, 40, 120, 120]` в обоих режимах, `B = 50`, `D` = индекс 2: прежнее `S_max = M[2] − B = 120 − 50 = 70` (суффиксный минимум не видел просадки до `D`) против нового `0` (`min free = 40 < 50`); для `S = 10` `m_after = 40 < B` → вердикт `TIGHT`, не `OK`. На G-001 числа не меняются (`min free` 93500 / 71000 ≥ B). Свойство-тест на ≥ 10³ журналах: `OK ⇔ S ≤ S_max_worse(D)` безусловно.

**G-001-late (C-058).** G-001 + плановый расход `P-X` −250000 на 2026-11-26 (без `is_obligation`). На `[10-04, 11-19]` `min free` 93500 / 71000, поэтому `STS(11-19)` = 43500 / 21000; на всём горизонте `min free` = −77800 (11-28, оба режима: `trough` 90000, `reserve_trough` 167800), поэтому `sts_horizon = STS(horizon_end) = S_max(as_of) = 0`, `short_to_buffer = 50000 + 77800 =` 127800, `baseline_below_buffer = true` → `S_max = 0`, `earliest = null`, вердикт `OK` невозможен. Правило показа: если `sts_horizon < sts`, экран добавляет строку «до конца горизонта (дата) — X» (G-001: «до конца горизонта — 0 (не хватает до буфера 1 278,00 €)»). Golden-тест различает `STS(T)` и `STS(horizon_end)`.

### TST-49 Монте-Карло: 8 лагов — `p_fail`, nearest-rank, Уилсон

### TST-50 Калибровка: квантили малых выборок и сжатие к prior

ALG-13 · REQ-053, 055. `p50` = 5, `p80` = 9, `p90` = 14 («наибольшее из 8»); `shrink_to_prior(5, 8, 7, 3) = round_div(8·5 + 3·7, 11) = 6`; новый клиент (лаги `[10, 12]`, `n = 2`, «медиана» везде nearest-rank `p50` = 10) → `round_div(2·10 + 3·7, 5) = 8` (C-052: прежнее 9 получалось по среднему 11). `shrink_to_prior` — подсказка интерфейса; единственное, что сдвигает дату в `expected`, — `lag_p50` при `n_obs ≥ 10` (C-053). ### TST-55 Backtest и гейт релиза: FRR ≤ 5 %, cry-wolf ≤ 50 % на ≥ 10 журналах

ALG-13 · REQ-176, 185. Гейт: FRR ≤ 500 bp и cry-wolf ≤ 5000 bp на ≥ 10 журналах добровольцев; гейт считается **по сумме счётчиков** по журналам, `N1 > 0` и `N2 > 0`. 200 вердиктов `OK`, 9 с пробоем → 450 bp, проходит; 120 тревог, 66 зря → 5500 bp, не проходит. При n_ok < 20 допустим 0 пробоев: 1 из 19 = 526 bp не проходит, 1 из 20 = 500 bp проходит. Рабочее определение исхода (C-055, X9, до первого замера; значения — гипотезы): «пробой буфера» для покупки `e` на момент `t` — `min` фактического `free` на `[e.date, e.date + H] < B(t)`, где `H = backtest.h_days = 30`; `actual_free(d)` — по полному журналу: фактический `trough` дня (расходы раньше доходов) минус `reserve_trough`; пробные покупки — реальные расходы без `is_obligation` и `is_estimate` с `|amount| ≥ θ`. Ошибка минимума (REQ-185): режим `plan`, физический `trough`, окно `backtest.min_window_days = 14`, `(факт − прогноз)/|прогноз|` в bp. Backtest-гейт — часть v1 (прототип его реализует; интерфейс backtest — v2, C-082). Учебный вектор MAE/bias/skill — в [ALG-13](../algorithms/alg-13-plan-vs-actual-calibration.md).

```pseudo
backtest_gate(journals):                      # анонимизация: сдвиг дат на 7·m дней, общий множитель сумм k ∈ [0,5; 2]
  K1 = N1 = K2 = N2 = 0
  for j in journals:
    for D in origins(j, step = h):            # окна не пересекаются
      v = verdict_at(state_at(j.events, recorded_at ≤ D), D)      # «как знали тогда»
      if v == OK:              N1 += 1; K1 += (пробой буфера в окне H = backtest.h_days)
      if v in {FRAGILE, NO}:   N2 += 1; K2 += (пробоя не было)
  return len(journals) ≥ 10 and N1 > 0 and N2 > 0 and 10000·K1 ≤ 500·N1 and 10000·K2 ≤ 5000·N2     # счётчики суммируются по журналам (C-055)
```

### Прогоны: правило «по одному файлу»

### Тесты todo и пропуски

В итоговом прогоне 2026-11-09 20 тестов помечены `{todo}` (промежуточный батч того же дня — 28; на 2026-10-28 было 26, на 2026-10-05 — 13, после волны 2 — 5); после правок FP-51 — 20. Упавший `todo` ошибкой не считается, поэтому набор не ломается; но пометка остаётся, пока её не снимут, и такой тест в счёте `todo` даже тогда, когда он проходит, — значит, число `todo` не равно числу открытых дефектов. Две группы.

## CI

В прототипе CI нет: набор запускается вручную по одному файлу (`npm run test:all` — 947 с на 202 файла 2026-11-09 (650 с — на 194 файлах 2026-10-28); `test:fast` — около 5 минут; `test:nightly` — с повышенными объёмами), конфигурации автозапуска в репозитории нет, и тест `check_script` проверяет, что её нет (хостинг не выбран, FP-40). Вместо неё — `npm run check` (`lint`, `lint:words`, `build:check`, `verify`, `contrast`; первая ошибка останавливает цепочку), перед релизом `npm run build:gate` (`lint:words` и `build_manifest --check`) и хук `.githooks/pre-commit` (`npm run lint:words`, подключается вручную; `RUNWAY_HOOK_SKIP=1` или `--no-verify` его отключают). Стадии ниже — проект для продукта.

| Стадия | Что запускается | Блокирует |
|---|---|---|
| Коммит | линтеры (`engine/`, словарь, обещания, метки `G-001.*`), `tsc --checkJs`, TST-01…43, 45…47, `arith.lock` | да |
| PR | то же + оракул (TST-53), фаззинг (TST-51), мутации (TST-52) | да |
| Ночью | фаззинг 10⁵ журналов, `hledger` при наличии (TST-44), производительность (TST-54), сеть и CSP (TST-59), двойная сборка (TST-60) | красная блокирует релиз |
| Релиз | backtest (TST-55), запись юридического ревью (REQ-183), срок давности обещаний 90 дней, «ARITH-CHANGE», манифест хэшей | да |

Времена прогона — цели до замера; тест переносится на стадию ниже, а не отключается.
