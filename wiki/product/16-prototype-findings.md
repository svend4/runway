# Находки прототипа

Прототип в `prototype/` проверил канон исполнением: [14 алгоритмов](../algorithms/alg-01-recurrence-expansion.md) реализованы, прогнаны на наборе G-001 и атакованы четырьмя «состязательными» тестерами. Страница сводит итог: что подтвердилось, какие баги найдены, какие места канона спорны и что с ними делать. Источник — `_ops/workflow3-result.json` (поля `layers`, `adversarial`, `fix`, `reconcile`), покрытие — `_ops/tst-coverage.json`. Все числа здесь — расчёт по введённым данным и правилам, не консультация; налоговые правила в прототипе — конфигурируемые данные пользователя.

Условные обозначения: **П-n** — подозрение на ошибку канона (порядковый номер в `adversarial.canon_suspects`, 1–33); **К-n** — кандидат в канон v1.2 (полный список — в `_ops/design-brief.md` §15, правки канона **не применены**, решение за владельцем). Улики-тесты: `dm` = `tests/adversarial/dates_money.test.mjs`, `sem` = `semantics.test.mjs`, `vio` = `verifier_io.test.mjs`, `gp` = `golden_properties.test.mjs`; число после двоеточия — строка файла на 2026-10-05.

## Подозрения на ошибки канона

33 подозрения сгруппированы по темам. «Код сейчас» — поведение после исправления багов. Решения: **принять** (в канон v1.2 с формулировкой К-n), **оставить** (код и канон не меняются, фиксируется todo-тест или оговорка). Отклонённые альтернативы названы в тексте.

### Журнал, арифметика, параметры

| № | Суть | Код сейчас | Решение |
|---|---|---|---|
| П-1 | формула `split_equal` и текст «по модулю с обратным знаком» дают разное при `total < 0` | по тексту: `(−7, 3) → [−3, −2, −2]`, обе реализации зеркальны | принять — К-1 |
| П-2 | буквальная формула `eff` даёт двойной учёт в цепочке a←b←c | `live` для замены, `eff` для revert | принять — К-2 |
| П-6 | «валидный Instant» не определён | календарно и по времени корректный момент (A-09) | принять — К-3 |
| П-32 | у параметров нет диапазонов (память `lag_pool`, `tools.max_calls`) | нечисловой `max_calls` → 12; диапазонов нет | принять — К-4; код доработать |

- **К-1** (П-1; Деление отрицательной суммы): `split_equal(total, n)` при `total < 0` равно `−split_equal(−total, n)`: больший по модулю остаток уходит первым элементам, `(−7, 3) → [−3, −2, −2]`; то же для `split_largest_remainder`. Формула `floor_div(total,n)+(k<floor_mod(total,n))` — только для `total ≥ 0`.
- **К-2** (П-2; Эффективность записей журнала): Запись `e` действует, если нет действующего `revert(e)` и нет живой замены. Замена живая, пока её не отменил действующий `revert`; замена, замещённая позже, остаётся живой и по-прежнему замещает `e` (цепочка a←b←c даёт одну действующую запись c). Действие самого `revert` определяется по `eff`: `revert`, замещённый исправляющим `revert`, не действует.
- **К-3** (П-6; Допустимый Instant): `Instant` = `YYYY-MM-DDTHH:MM:SSZ` с корректными значениями: месяц 1–12, день не больше длины месяца, час ≤ 23, минуты и секунды ≤ 59 (секунда 60 не допускается); иное — `E_SCHEMA` (`recorded_at_not_instant`).
- **К-4** (П-32; Диапазоны параметров): У каждого параметра §2.0 есть тип и допустимый диапазон. Нечисловое или вне диапазона значение при записи `params.set` — `E_SCHEMA`; из чужого журнала — значение по умолчанию. Границы-предложение (подтвердить владельцем, вывод): `tools.max_calls` ∈ [1, 12], `worse.income_delay_days` ∈ [0, 365], `match.window_days` ∈ [0, 31], `horizon_days` ∈ [1, 3660].

**Исправлено сразу.** Страница `compat.html` по-прежнему говорила «приложение эту возможность не использует» про File System Access, хотя автозапись FP-19 её использует: тексты `compatpg.d_fsa_pickers`, `d_fsa_opfs`, `d_fsa_absent` (RU и EN) переписаны («приложение может писать копию журнала в выбранный файл» / «автозапись недоступна, остаётся ручная выгрузка»).

**Замечено, не исправлялось.** (1) В блоке «Сообщить об ошибке» при пустом журнале ошибок текст обещает «в отчёт войдёт только версия движка», а в отчёте показана строка `code: E_UNKNOWN` — вводит в заблуждение, нужна пустая запись или текст без обещания (низкая важность). (2) Страница `coldstart.html` под `node serve.mjs` не откроет приложение из-за `frame-ancestors 'none'` (названо в самой странице); не проверялась. (3) Запас бюджета на 10³ событиях в браузере на загруженной машине мал (80 из 100 мс) — замер повторить на освобождённой машине и на устройстве (FP-40).

**Не проверено в браузере.** Фактическая запись автокопии в файл (окно выбора файла из скрипта не открыть); раскрытие и закрытие «Ещё» на телефоне; ширины 600 и 1024 px при шрифте 200 %; «Освободить остаток»; разбор файла ≥ 128 КБ в Worker; часы из CSV и обмен двумя ногами (FP-29); метрики качества из окон прогноза (FP-22); две вкладки; Safari и iOS; PWA (сервис-воркер во встроенном браузере недоступен).

**Урок процесса.** Независимая проверка FP-49 нашла регрессию средней тяжести, которую тесты автора не видели: сначала кнопка «Вернуть выбранный набор» оказалась отключена и для правленого встроенного набора — единственного состояния, где она что-то возвращает (заглушка DOM различала «источник» и «встроенный набор» только по значению `custom`). Исправление отдаёт в подписи признак встроенного набора (`builtin`), а страница загружает только набор, который совпадает с текущим.

**Не проверялось в браузере:** подпись безымянного файла (ADV-05; нужен выбор файла — покрыто тестами `fp49_pure`), порядок озвучки скринридером (замена текста живой области целиком: возможна повторная озвучка сообщения вместе с вердиктом), светлая и тёмная темы отключённой кнопки глазами, PWA (сервис-воркер во встроенном браузере недоступен), Safari и iOS.

**Продуктовый риск (ADV-11, FP-49).** Сообщение о действии и вердикт попадают в живую область одной строкой, только если вердикт пришёл не позже 600 мс после сообщения (`SAY_JOIN_MS`). На медленном устройстве, где расчёт в Worker идёт дольше, вердикт заменяет сообщение, и скринридер озвучит сообщение только в том случае, если успеет прочитать его до замены. Проверка `fp49_boot` ждёт настоящие 750 мс, поэтому на перегруженной машине она может падать; подмена часов через порт демо (`ids.clock_ports`) пока не сделана.

## Тестовая сеть и часы: что нашли FP-24 и FP-50 (2026-10-27…11-09)

Пакеты, которые проверяли тестовую сеть (FP-24, 2026-10-27…28) и часы (FP-50, 2026-11-09). Записи — из тестов и отчётов прогонов; браузер для этих пакетов не запускали.

**FP-24: полный фаззинг 10⁵ нашёл настоящий дефект движка.** Разреженный массив в `entries_of` (`engine/validate_ws.mjs`) давал `validator_internal:TypeError` на итерации 57 010 из 100 000 (`_ops/fuzz-nightly.json`, `full.previous_runs`, запуск от 2026-10-27: `complete: false`, одно исключение). Исправлено одной строкой (`Array.from`): дыра становится записью `record_not_object` с индексом, вывод `analyze` не менялся, замок вывода совпал. Повторный полный прогон 2026-10-28 завершён: `complete: true`, исключений 0, 552 с. Он шёл на коде до правки FP-49 (проверка длины массива до развёртки). Прогон 2026-11-09 на текущем коде: `complete: true`, исключений 0, 1126 с (при 921 МБ свободной ОЗУ) — оговорка снята ([REQ-158](../../_ops/gap3/req-quality-ops.json)); предыдущие запуски сохранены в `previous_runs`, находка FZ-1 — в `findings`.

**FP-24: TST-32 шёл «вхолостую».** Проверка нашла, что пары план/факт были в 6 из 1000 журналов, то есть инвариант почти ничего не сравнивал. Обогащение журналов поднимает число пар до 528 из 1000; тест теперь проверяет то, что заявляет.

**FP-24: что добавлено.** Девять property-тестов TST-31…39 на 1000 журналах общего генератора; замок вывода движка на 500 журналах (`tests/engine.lock.json`, `engine_version` 0.1.0); 66 мутаций расчётного ядра (65 убиты, одна V07 эквивалентна); малые журналы; сквозной прогон по одному файлу (`tools/run_all_tests.mjs`). Прогон 2026-11-09: `properties` 13/13, `engine_lock` 12/12, `mutate_engine` 13/13, `small_journals` 11/11.

**FP-50: матрица часов и поясов** (`tools/clock_matrix.mjs`, пять профилей: base, shift_far, shift_past, midnight_east, midnight_west). Матрица нашла и исправила:

- `tests/fp18_adv.test.mjs` (ADV-01/02) — гонка мастера импорта: баннер «Проверяю файл» гас после фиксированного окна 1,0–1,4 с, а заглушка Worker разбирает файл на главном потоке и под нагрузкой не успевала. Исправлено ожиданием по состоянию экрана (предел 20 с). Повторов в артефактах нет: в каждом из пяти профилей один прогон `fp18_adv` (3 теста из 3), все зелёные (`_ops/impl/run/clock-matrix-*.json`).
- **Дефект правила 10 в мастере импорта** (`demo/import_wizard.mjs`: `pick_csv`, `pick_profile`, `pick_hl`): после `await` результат чтения файла рисовался локальным `redraw` в отсоединённый узел. Исправлено: результат пишется в мастер, живой экран рисуется через `redraw_live`; тесты D-1…D-3 были красными на старом коде.
- `tools/lint_vocab.mjs` — «сегодня» по умолчанию бралось как UTC-дата (`toISOString`). Матрица этого не показала (сдвиг на сутки не переворачивает правила тестов), найдено при чтении кода; исправлено через `local_today_iso()`.
- `tests/v0.test.mjs` (REQ-180, TST-59) — страница стартовала с часами машины. Теперь `boot_v0(ports)` принимает порт часов; тесты стартуют с `PAGE_CLOCK` (4 октября 2026, 09:00 UTC, пояс 0).
- `demo/v0.mjs` (`boot_v0`) — порт без `tz_offset_min` давал UTC-дату; теперь берётся смещение устройства (тест D-4). `local_today` без смещения по-прежнему UTC: это контракт `tests/as_of.test.mjs`, менять его — решение владельца.
- `tests/num_labels_coverage.test.mjs` — правило «измерение старше 90 дней» в `lint_vocab` сверяло дату `journal_speed` (2026-10-05) с часами машины; опорная дата теста — 2026-10-28, само правило прежнее.
- Нагрузочные сбои в базовом профиле — `tests/timeline.test.mjs` (TST-54), `tests/fp21_adv.test.mjs`, `tests/calc_async_boot.test.mjs`, `tests/calc_async_model.test.mjs`: повторы по одному зелёные; причины — фиксированное ожидание 700 мс в `tests/dom_boot.mjs`, бюджет блокировки 50 мс, гонка с ответом Worker.

**Итог матрицы.** В профилях shift_far, shift_past, midnight_east и midnight_west датозависимых сбоев после исправлений нет; сверх base не разобранных сбоев нет. Красный в base и во всех профилях был один — `tests/fp30_adv.test.mjs` (ADV-2, ADV-3): вики и отчёт не знали файлов FP-49; исправлено в FP-51.

**Открыто после FP-50.** Вторая независимая проверка вернула четыре low, они не исправлены: `tools/README.md` пишет «быстрый профиль — 167 файлов» (фактически 172); перечень изменений существующих тестов не полный в decisions и shared_files_touched; первый прогон base (timeline, fp21_adv) не прослеживается в артефактах (в JSON нет `attempts` и `retried`); тест D-4 в `tests/v0.test.mjs` зависит от пояса и даты (на TZ=Europe/London 2026-11-09 даты расходятся).
