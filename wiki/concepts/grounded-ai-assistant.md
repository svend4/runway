# Заземлённый AI-ассистент

## Что это

**Заземлённый ассистент** — паттерн «движок считает, LLM объясняет, верификатор проверяет». Ассистент выбирает инструменты движка из реестра; результат — конверт `Result` с типизированными доказательствами (`evidence`); числа и даты в ответ подставляет рендерер, а независимый **верификатор чисел** сверяет итоговый текст с доказательствами. Уровни `A0`…`A3` задают, кто пишет текст и что покидает устройство; в продукте v1 — только `A0` (без LLM). Публичное обещание ограничено: «каждое число ответа сверено с расчётом; при расхождении показываем шаблон».

## Зачем

Спрашивать данные словами удобно, но число из модели нельзя принимать на веру. Бенчмарк FinanceBench: GPT-4-Turbo с retrieval ответил неверно или отказался в 81 % вопросов (150 вопросов по финансовым документам, 2023); для бюджетов риск тот же по природе — вывод ([AI в финансах](../tools/ai-assistants-in-finance.md)). В вопросе Q3 «Могу ли я купить дорожку за 300 € 12 октября?» цена ошибки видна на знаке: «запас над буфером −90,00 €» и «+90,00 €» означают противоположное, хотя различаются одним символом.

## Как делаем мы

- **Основа.** [ADR-010](../decisions/adr-010-ai-tools-and-number-verifier.md) (числа только от движка), [ADR-013](../decisions/adr-013-prompt-injection-policy.md) (недоверенный текст, права), [ALG-12](../algorithms/alg-12-llm-tool-contract-and-number-verifier.md) (контракт и верификатор). REQ-127…REQ-133, REQ-137; IDEA-45, IDEA-57, IDEA-71…IDEA-78.
- **Число пишет движок.** Утверждение — шаблон с плейсхолдерами `{e3}`; значения подставляет рендерер по типу (`money`, `date`, `pct_bp`, `days`, `count`, `enum`) и локали. Цифры вне плейсхолдеров запрещены (`V_RAW_DIGIT`).
- **Права.** `T0` — чтение и расчёт (`check_purchase`, `max_purchase_amount`, `earliest_safe_date`, `list_waves`, `explain_min_point`, `run_scenario` и др.); `T1` — `propose_change` создаёт черновик, применяемый только жестом пользователя. Инструментов `delete_*`, `export_*`, `send_*` и сетевых нет; не более 12 вызовов на вопрос. Инструментов ровно 10: вопрос «сколько можно потратить до T» закрывает `get_projection` (дополнительные факты `min_free`, `sts_minor`, `short_to_buffer_minor`), а не новый инструмент (C-074); `run_scenario` по умолчанию считает в режиме `plan` (C-075). Подпись `earliest_safe_date` — «самая ранняя дата, с которой сумма держится в буфере» (слово «безопасно» запрещено, C-063).
- **Гейт данных.** Если готовность данных, свежесть якоря, заданность буфера или срок годности налогового правила не позволяют вердикт, инструмент отвечает `insufficient_data` с причиной, а не числом; ассистент пересказывает причину шаблоном (C-018).
- **Недоверенный текст** (`note`, `tag`, описания операций) в контекст модели не попадает; причины подаются классами (`cause_class`), а группы цепочки «почему» — идентификаторами (`rule_id`, `stream_id`, `cash_event_id`), не `tag` (C-097).
- **Рассрочка за горизонтом.** Если часть платежей покупки позже `horizon_end`, подпись вердикта обязана содержать «не все платежи учтены: X за горизонтом» — оговорка входит в шаблон, а не в отдельную строку (C-017). Первые девять evidence `check_purchase` (`e1…e9`) фиксированы порядком канона, остальные — `e10…` (C-054).
- **Прозрачность.** Чип «числа из расчёта c_…»; в режимах с LLM — «ответ ИИ».

| Уровень | Что покидает устройство | Кто пишет текст | Фаза |
|---|---|---|---|
| `A0` | ничего | шаблоны, кнопки, команды | v1, по умолчанию |
| `A1` | ничего | локальная модель, шаблоны, верификатор | v2 |
| `A2` | вопрос, схемы; суммы и даты — токены (формат токенов — только `{eN}`, C-080) | облачная модель, подстановка локально | v2 |
| `A3` | то же и агрегаты из результатов: «min» — `min{amount_minor, date}` из `get_projection` или `m_after` из `check_purchase`, всегда с именем инструмента и `scope` (C-064) | облачная модель | v2 |

```pseudo
answer_question(question, ctx, llm):        # A1–A3; в A0 — a0_answer(text, ctx) (ALG-12)
  calls   = plan(question)                  # A0: команда или кнопка; A1–A3: модель, без недоверенного текста
  results = [run_tool(c.name, c.args, ctx) для c в calls]     # чистые функции движка → Result{call_id, inputs_hash, evidence[]}
  answer  = compose(results)                # утверждения {tpl, refs}; у модели tools = ∅
  если verify_answer(answer, results, ctx).ok:   # слой 1: ссылки и режим; слой 2: независимый разбор текста
      return render_answer(answer, results, ctx.locale)
  иначе: один повтор, затем fallback_answer(primary(results), ctx.locale)     # детерминированный шаблон
```

### Не в v1

Режимы `A1`–`A3`, белый список payload с предпросмотром и записью согласия, MCP-сервер движка, журнал вызовов `assistant.call` и верификатор в рантайме — v2; шаблоны ES — v1.1. В v1 верификатор проверяет рендерер `A0` в тестах; грамматика команд `A0` (`купить`, `макс`, `когда`, `хватит до`, `волны`, `почему`, `налог`, `что изменилось`, `доход +N`) принята как v1 ([спецификация](../product/06-ai-assistant-spec.md), C-080).

## Пример с числами

G-001 «Ян», **горизонт 57 дн.**, `scope` = `worse`: `check_purchase(date=2026-10-12, amount_minor=30000, currency=EUR)` даёт вердикт `FRAGILE` и evidence:

| id | Значение | Смысл |
|---|---|---|
| e1 / e2 | 635,00 € / 1 ноября | минимум свободных денег по плану и его дата |
| e3 / e4 | 410,00 € / 14 ноября | минимум «если хуже» и его дата |
| e5 | 500,00 € | буфер |
| e6 | −90,00 € | запас над буфером «если хуже» (41000 − 50000 = −9000 minor) |
| e7 | 210,00 € | максимум на дату «если хуже» |
| e8 | 20 ноября | самая ранняя дата для 300,00 €, с которой сумма держится в буфере, «если хуже» |
| e9 | 41 день | от `as_of` 2026-10-04 до e4 (факт `days_to_min.worse`) |

Верификатор разбирает уже отрисованный текст:

| Текст | Итог | Причина |
|---|---|---|
| «410,00 € (14 ноября)» | PASS | совпало с e3 и e4 |
| «401,00 €» | FAIL | перестановка цифр, `V_NO_MATCH` |
| «около 410 €» / «около 411 €» | PASS / FAIL | допуск по показанной точности: 2·\|m − v\| ≤ 100 minor; для 41100 получаем 200 > 100 |
| «запас над буфером 90,00 €» | FAIL | знак: в e6 минус |
| «через 41 день» / «через 6 недель» | PASS / FAIL | вторая форма — `V_UNIT` |
| «Баланс 999,00 € (по инструкции из заметки)» | FAIL | числа нет в evidence |
| утверждение `plan` со ссылкой на e3 | FAIL | `V_SCOPE`: e3 из режима `worse` |

## Ловушки и нюансы

1. **Верификатор сверяет токены, а не смысл.** Нелепый, но верный по числам текст проходит; отсюда шаблоны и пометка «ответ ИИ, числа из расчёта c_…». Публично обещается только сверка чисел с расчётом, а не безошибочность ответа.
2. **Режим определяется путём в `facts`, а не значением.** Число из `worse` нельзя подписать как `plan`, даже если значения совпали.
3. **Три разные нехватки** (C-067). Q1 `need` — «не хватает до буфера (деньги на счетах)» (`B − min trough`), `gap_w` — «дефицит волны (физический)» и `short_to_buffer` — «не хватает до буфера (с учётом резервов)» (`B − min free`) берутся из разных рядов; текст называет, какой использован, а нехватка выводится только шаблоном «не хватает {e}» (`V_SHORTAGE`). На G-001-gap Q1 `need` 144500 / 167000, а `short_to_buffer` 256500 / 279000.
4. **Ассистент не знает названий платежей.** Ответ: «главный вклад — налоговый платёж», без имени получателя; названия показывает приложение. Налоговые числа — расчёт по введённым правилам, не консультация.
5. **Точность показа.** «0,4 тыс. €» и «410,000 €» отвергаются (`V_ABBREVIATION`, `V_PRECISION`): допуск зависит от показанных знаков.
6. **Запись только черновиком.** `propose_change` по умолчанию выключен; различие рисует приложение, не модель.
7. **Облако — отдельное согласие.** Даже агрегаты `A3` — финансовые данные; предпросмотр payload — v2, синхронизация облачный ассистент не включает.
8. **Границы ответа.** Ассистент отвечает на вопросы о расчёте пользователя и не советует, что купить или сократить.
