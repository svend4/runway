# Модель почасового дохода

## Что это

**Поток дохода по часам** (`IncomeStream`) — данные пользователя: ставка за час `rate_minor`, часы за расчётный период в целых минутах (`min`, `exp`, `max`), граница периода, лаг выплаты `pay_lag_days`, политика выходных, при необходимости порог и множитель переработки. Поток порождает плановые поступления: сумма `gross = mul_div(rate_minor, weighted_minutes, 60, rounding)` (одно округление за период; без переработки `weighted_minutes = m`), дата `shift_by_policy(period_end + pay_lag_days, weekend, calendar)`. Диапазон дохода — `gross(min)`, `gross(exp)`, `gross(max)`; в расчёте участвует `exp`. **Недоработка** — отставание факта часов от плана к дате.

## Зачем

Пятый принцип статьи Т—Ж: ставка и норма выработки встроены в график ликвидности; релокация принесла почасовую оплату, плавающий график, переработки и бонусы ([статья](../../raw/01-tj-salkov-article.md)). У почасовика самое большое «может быть» — доход: сколько часов будет и когда придёт выплата. В G-001 «Ян» сентябрьская выплата 2 880,00 € (96 ч) уже в остатке, октябрьская 2 790,00 € (93 ч) ожидается 5 ноября; от её даты зависит минимум денег и вердикт по покупке.

## Как делаем мы

- **Минуты и целые деньги:** `gross = mul_div(rate_minor, min(m, T)·10000 + max(0, m − T)·mult_bp, 600000, rounding)`; `weighted_minutes` — справочная дробь, не округляется; округление — **один раз** за период, режим — `params.rounding` (`half_even` по умолчанию; у потока своего `rounding` нет; [ADR-002](../decisions/adr-002-money-minor-units.md), C-028, C-029).
- **Даты:** выплата считается от границы периода, выходной сдвигается политикой `weekend`; `skip` для дохода запрещён ([ADR-003](../decisions/adr-003-civil-dates.md)). Прошлые выплаты — факты, в план не входят; выплата в день `as_of` ещё «впереди».
- **Режим `worse`** сдвигает дату выплаты на `worse.income_delay_days` (14), сумму и часы не меняет; «часы по минимуму» — отдельный чип сценария (v1.1).
- **Недоработка** показывается рядом с планом и его не переписывает: оценка `est_minutes` — отображаемая (в v1 не меняет план, автоматическая замена `exp_minutes` по темпу — v2, C-033); принять оценку — значит записать `exp_minutes` периода.
- **События потока** несут `stream_id` (`rule_id = null`), `occ_key = stream_id@номинальная_дата`; налоговое правило сопоставляется по `applies_to.stream_ids` (C-025). Для `period = biweek` обязательна `cutoff.anchor` — дата любой границы периода (C-026).
- **Налоговая аллокация** считается от `gross` потока ([налоговый конверт](tax-envelope.md)).
- Алгоритм — [ALG-07](../algorithms/alg-07-hourly-income.md); требования REQ-073…REQ-075; идеи IDEA-18, IDEA-42; определение D-19 — в [каноне проекта](../../_ops/design-brief.md).

```pseudo
gross_pay(rate_minor, minutes, overtime, rounding):
  если overtime == null: return mul_div(rate_minor, minutes, 60, rounding)
  T = overtime.threshold_minutes
  wx = min(minutes, T)·10000 + max(0, minutes − T)·overtime.mult_bp         # взвешенные минуты ×10000, точное целое
  return mul_div(rate_minor, wx, 600000, rounding)                           # единственное округление
shortfall:  short = plan_to_date − actual;  effect = mul_div(short, rate_minor, 60);  est = actual + max(0, exp − plan_to_date)
```

### Не в v1

Автоматический пересчёт ожидаемого дохода по фактическому темпу (`rho`, EWMA) — v2 (в v1 — отображаемая оценка); недельный порог переработки при месячной выплате — v1.1 (C-027); импорт часов из CSV и чипы `hours_min`, `hours{stream_id, minutes}` — v1.1; несколько ставок в одном потоке не планируются.

## Пример с числами

G-001, **горизонт 57 дн.**: ставка 3000 (30,00 €/ч), `period = month`, лаг 5 дней, `weekend = next`.

| Величина | Расчёт | Результат |
|---|---|---|
| Октябрь, `exp` | 93 ч = 5580 мин; `mul_div(3000, 5580, 60)` | 279000 (2 790,00 €) |
| Октябрь, `min` / `max` | 80 ч = 4800 мин / 110 ч = 6600 мин | 240000 / 330000 |
| Дата выплаты | 31 окт + 5 дн, четверг | 2026-11-05 |
| Ноябрь | 30 ноя + 5 дн = суббота 12-05, `next` | 2026-12-07, вне горизонта 57 дн. |
| Переработка (`period = week`) | 46 ч за неделю, порог 40 ч, ×1,5: `mul_div(3000, 2400·10000 + 360·15000, 600000)`, взвешенных минут 2940 | 147000 |
| Ничья округления | 2401 мин, порог 2400, `mult_bp = 12500`: `mul_div(3000, 24012500, 600000)` = 120062,5 | `half_even` 120062, `half_up` 120063 |
| Недоработка на 10-20 | темп 5580/31 = 180 мин/день; план 20·180 = 3600; факт 52 ч = 3120 | `short` = 480 мин, эффект `mul_div(480, 3000, 60)` = 24000 |
| Пересчёт при `ρ = 1` | `est = 3120 + (5580 − 3600)` = 5100 мин | 255000 = 279000 − 24000 |

- Диапазон меняет `close` 11-05 (до прихода 205500): 445500 / 484500 / 535500.
- В `worse` те же 279000 приходят 11-19: минимум `trough` 183000 (11-14) вместо 205500 (10-31), конец горизонта 340000 в обоих режимах.
- Налоговая доля 20 % (иллюстрация, не консультация): 55800 от 279000, 48000 и 66000 от границ диапазона.
- Сентябрь: 96 ч = 5760 мин → 288000, выплата 10-02 уже в якоре 400000 и в план не попадает.

## Ловушки и нюансы

1. **Часы — целые минуты.** Дробные часы копят погрешность; «93:00» хранится как 5580.
2. **Округление на уровне периода — один раз.** Сумма округлённых частей может отличаться от `gross` целого периода на единицы minor, поэтому считается итог периода, а не сумма недель. Взвешенные минуты при дробном множителе переработки не округляются (C-028): при `mult_bp = 15000` 2401 минута даёт ровно 120075, 2403 — 120225; отдельное округление минут (до 120100 и 120200) отменено. Расхождение с работодателем, округляющим минуты отдельно, — до `rate/120` minor на выплату.
3. **Порог переработки относится к периоду потока:** 40 ч — порог недели для потока `week`, а не дня; недельный порог при месячной выплате в v1 не выражается (нужны часы по неделям, C-027).
4. **Выходной день выплаты** сдвигает дату (12-05 → 12-07); при горизонте 180 дней ноябрьская выплата входит в ряд, при 57 — нет, и числа G-001 другие.
5. **Закрытый период без факта** считается по `exp` с предупреждением: пока пользователь не введёт часы, «ожидаемо» остаётся планом.
6. **`worse` не уменьшает часы.** Задержка и недобор часов — разные допущения, их не складывают в один режим.
7. **Недоработка — информация, а не прогноз.** Темп 180 мин/день предполагает равномерную работу; `short < 0` — опережение, знак сохраняется.
8. **Ставка в другой валюте** переводится в валюту решения по курсу `spot` ([мультивалютность](multi-currency-fx.md)).
