# Правила повторения

## Что это

**Правило повторения** (`Rule`) — данные: частота `freq` (D/W/M/Y), `interval`, дни (`by_weekday`, `by_monthday`, `by_workday`), `start_date`, конец (`until_date` или `count`), политики конца месяца `month_end` (`clamp`, `skip`, `next_first`) и выходных `weekend` (`keep`, `prev`, `next`, `skip`), календарь и `exdates`. Вхождения вычисляются на лету и не хранятся. **Номинальная дата** считается от `start_date` без дрейфа; **эффективная** — после сдвига по календарю или переноса. Ключ `occ_key = rule_id@nominal_date` (для потока часов — `stream_id@nominal_date`; `rule_id` и `stream_id` не совпадают, C-025) не меняется при сдвигах, поэтому факт сопоставляется с тем же вхождением. Правка одного вхождения — `Override` (перенос, пропуск, другая сумма), серия не разрывается.

## Зачем

«25-го разом аренда, ЖКХ, страховки» — второй вопрос автора статьи Т—Ж: сколько останется до прихода денег ([статья](../../raw/01-tj-salkov-article.md)). Дата решает ответ. В G-001 «Ян» 25 октября — воскресенье, и при `weekend = next` аренда с ЖКХ уходят 26-го: «хватит ли к 25 октября» даёт минимум 317500 (24 октября), «к 26 октября» — 215500, то есть 102000 переехали на день позже.

## Как делаем мы

- **От начала серии:** `nominal_k = add_months(start, k · step)`; день берётся из исходной даты, в коротком месяце срабатывает `clamp_day` ([ADR-003](../decisions/adr-003-civil-dates.md), REQ-008).
- **Эффективная дата** = `override(n) ?? shift_by_policy(n, weekend, calendar)`; перенос `move` задаёт дату точно, без повторного сдвига (REQ-010).
- **Календарь — данные пользователя:** `weekend_dows` (по умолчанию суббота и воскресенье) и `holidays`; пакетов праздников в v1 нет, смена календаря — запись журнала, прошлые факты не меняет (REQ-009).
- **Номинальные поля:** `exdates`, `until_date`, `count` относятся к номинальной дате; окно запроса фильтрует эффективную. `count` считает номинальные даты после применения `month_end` и до `exdates`; при заданных `count` и `until_date` побеждает более ранний предел (C-002).
- **Семантика `by_*`** (C-002): неделя для `by_weekday` — с понедельника, поле допустимо только при `freq = W`; `by_monthday` и `by_workday` допустимы только при `M` и взаимоисключающи; для `Y` — без `by_*`. Правило с `by_workday` без календаря не разворачивается: `E_SCHEMA` (C-003).
- **Знак суммы** (C-001): `amount{exp_minor, min_minor?, max_minor?}` — со знаком, согласованным с `kind` (расход < 0, доход > 0, `exp_minor ≠ 0`); проверяет `validate_rule`.
- **Переопределения** (C-003) передаются массивом или индексом по `occ_key`; при повторе ключа побеждает последний.
- **Вхождения одного дня не сливаются:** развёртка отдаёт их по отдельности, суммирует проекция ([ALG-02](../algorithms/alg-02-timeline-projection.md)).
- Алгоритм — [ALG-01](../algorithms/alg-01-recurrence-expansion.md); идеи IDEA-04, IDEA-05, IDEA-06; тесты TST-11…TST-15; определения — в [каноне проекта](../../_ops/design-brief.md).

```pseudo
nominal(start, k, interval) = add_months(start, k · interval)             # всегда от start
effective_date(rule, n, cal, overrides):
  o = overrides[rule_id + '@' + format_date(n)]
  o.action == skip → null;  o.action == move → o.date;  иначе shift_by_policy(n, rule.weekend, cal)
```

### Не в v1

«Второй вторник» (n-й день недели месяца), `BYMONTH`, `by_monthday` для года, пакеты праздников со сроком годности и версии правила с датой вступления — v2. Квартальный платёж в v1 — `freq = M`, `interval = 3`.

## Пример с числами

| Вход | Результат |
|---|---|
| Ежемесячно от 2026-01-31, `clamp`, `k = 0…5` | 01-31, 02-28, 03-31, 04-30, 05-31, 06-30 (наивное «+1 месяц» даёт 31 → 28 → 28 → 28) |
| То же, `k = 13` / `k = 25` | 2027-02-28 / 2028-02-29 |
| `R-RENT`, 25-е, `next`: 2026-10-25 (воскресенье) | эффективная 2026-10-26; 11-25 (среда) — без сдвига |
| Та же дата, `next` / `prev` / `keep` | 10-26 / 10-23 / 10-25 |
| 3-й рабочий день ноября 2026 | 2026-11-04 (1 ноября — воскресенье) |
| Последний рабочий день октября 2026 | 2026-10-30 (31-е — суббота) |
| «Раз в 2 недели» от 2026-10-02 | 10-02, 10-16, 10-30, 11-13 |
| `R-GROC`, каждая суббота, горизонт 57 дн. | 8 вхождений (10-10 … 11-28); `exdates = [2026-10-17]` оставляет 7 |
| `Override{R-RENT, nominal 2026-11-25, move → 2026-11-27}` | `occ_key = R-RENT@2026-11-25`, `date = 2026-11-27` |

- **G-001, горизонт 57 дн.:** 14 вхождений (аренда 2, ЖКХ 2, связь 2, продукты 8). Начала серий заданы каноном (C-011): `R-RENT` и `R-UTIL` — 2026-01-25, `R-PHONE` — 2026-01-09, `R-GROC` — 2026-01-03 (суббота); на окно они не влияют. Сумма правил −289000; с налоговым платежом −50000 (плановая запись пользователя, не консультация) итог −339000, как в канонической сводке. На 10-26 два вхождения: аренда −90000 и ЖКХ −12000, вместе −102000.
- **Сдвиг через границу окна:** правило от 2026-01-31 с `next`: номинальная 10-31 — суббота, эффективная 11-02 попадает в окно ноября, поэтому развёртка расширяет окно на максимальный сдвиг и перенос.
- **Дни недели:** `EpochDay` 20751 (2026-10-25) → `dow` = floor_mod(20751 + 4, 7) = 0, воскресенье.

## Ловушки и нюансы

1. **Дрейф.** Прибавление месяца к предыдущему вхождению теряет 31-е навсегда; поэтому каждая дата считается от `start_date`.
2. **Конец месяца.** День 29–31 в коротком месяце обрабатывается политикой `month_end`; для 29 февраля в годовом правиле `clamp` даёт 28.02, `skip` — только високосные годы.
3. **Сдвиг выходных переносит дату через границу окна:** 31 октября (суббота) → 2 ноября; вхождение принадлежит окну по эффективной дате.
4. **`exdates` — номинальные даты.** Исключить субботу 10-17 можно только по номинальной дате; эффективная после сдвига не сработает.
5. **`weekend = skip`.** Вхождение пропадает, но номер в `count` остаётся занятым.
6. **Календарь устаревает.** Забытый праздник даёт неверную дату платежа; если все семь дней выходные, правило отвергается с `E_RULE_INVALID`.
7. **Ключ по номинальной дате.** Перенос меняет `date`, а не `occ_key`; два вхождения в один день имеют разные ключи и обе учитываются.
8. **Override на несуществующую номинальную дату** игнорируется: ключ ни с чем не совпал.
