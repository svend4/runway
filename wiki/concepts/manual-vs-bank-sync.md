# Ручной ввод и банковская синхронизация

## Что это

**Ручной ввод** — данные вводит пользователь или загружает из файла; банковских API в v1 нет. **Банковская синхронизация** — получение операций и остатков из банка через агрегатор или коннектор. Runway v1 выбирает ручной путь осознанно: факт вводится коротко (сумма → Enter), планы заданы правилами, CSV импортируется по профилю-данным с сухим прогоном и дедупликацией, выход — JSON, CSV и hledger. Банковских агрегаторов в ядре нет; возможный плагин-импортёр — вне ядра, не раньше v3.

## Зачем

Автор статьи Т—Ж отказался от банковского API: при счетах в ЕС, иностранном ИП, крипте, наличных и инвойсах полуавтоматический ввод гибче ([статья](../../raw/01-tj-salkov-article.md)). Цена выбора — риск № 1 красной команды (RISK-01): первый прогноз красив, через 3–4 недели остаток расходится с банком, и человек возвращается в таблицу ([критика](../ideas/red-team-critique.md)). Поэтому Runway не обещает «автоматику», а защищается от устаревших данных: якорь остатка, плашка свежести, готовность данных 0–4.

## Как делаем мы

- **Решение и требования.** [ADR-011](../decisions/adr-011-manual-entry-csv-hledger-import.md): ручной ввод — нормальный путь, а не «режим без банка». REQ-090…REQ-096, REQ-099…REQ-102; идеи IDEA-32, IDEA-56, IDEA-65, IDEA-84, IDEA-85, IDEA-91; алгоритм — [ALG-14](../algorithms/alg-14-hledger-export-csv-import.md).
- **Профиль как данные.** `ImportProfile` задаёт кодировку, разделитель, `skip` (число строк преамбулы перед обязательным заголовком), формат даты, знак суммы, десятичный знак, валюту; метки — литеральные правила по нормализованному описанию (префикс при ведущем `^`, иначе подстрока; **без regex**, чтобы профиль-данные не вешал разбор); деньги разбираются строками, без float; профиль с исполняемым полем отвергается схемой. Колонки внешнего идентификатора в v1 нет (FITID — v2); знак внутри колонки дебета/кредита — отказ `sign_in_debit_credit` (C-044). Профиль хранится записью журнала `profile.set`.
- **Идемпотентность.** `dedup_key = hex(sha256(acc|date|amount_minor|currency|norm(desc)|k))[0:16]`, `k` — номер среди одинаковых в партии. Партия — запись журнала, откат — `revert` всех её записей; смена описания банком даёт «возможного двойника», а не молчаливое слияние.
- **Свежесть вместо автоматики.** Якорь остатка — подтверждённая цифра с выписки; его возраст управляет плашкой и вердиктом Q3 ([ALG-13](../algorithms/alg-13-plan-vs-actual-calibration.md)). Возраст считается по самому несвежему `operating`-счёту: один свежий счёт не скрывает устаревший; у счёта без якоря возраст неизвестен — отказ вердикта с причиной `no_anchor` (C-010).

```pseudo
{candidates, rejects, rows_total} = parse_with_profile(profile, text, ctx)     # ctx = {account_id, account_currency, as_of}; без float
для c в candidates:
  если c.dedup_key ∈ existing_keys:   дубликат        # c.dedup_key = dedup_key(acc, date, amount_minor, currency, desc, k), ALG-14
  иначе:                              распознана
отклонённые строки — rejects(reason)
инвариант: распознано + отклонено + дубликатов = число строк; до подтверждения state_hash журнала не меняется

age = as_of − min(дата последнего якоря)  по operating-счетам;  нет якоря → block (no_anchor)
age > 7  → плашка «не учтено ≈ unlogged_rate · age»;   age > 21 → вердикт Q3 и «можно потратить» заменены на «данных мало»
```

### Не в v1

Импорт hledger-журнала (подмножество) и мастер миграции из таблиц — v1.1. Адаптеры Дзен-мани и CoinKeeper (CSV; API с OAuth как запасной путь) и OFX с приоритетом `FITID` — v2. Плагин банка — v3, вне ядра: список разрешённых хостов, секреты в локальном хранилище под паролем, выход — только кандидаты в тот же конвейер дедупликации.

## Пример с числами

G-001 «Ян», `as_of` 2026-10-04 (горизонт 57 дн.).

- **Якорь.** Ян вводит остаток 400000 (4 000,00 €) на 2026-10-04: он уже включает сентябрьскую выплату 288000 от 2026-10-02. `age` = 0, готовность 4, Q3 разрешён.
- **Свежесть.** Прошлые расхождения якорей: 8400 за 7 дней и 15000 за 10 дней — 1200 и 1500 в день. `unlogged_rate = round_div(1200 + 1500, 2) = 1350`. При `age` = 9 не учтено ≈ 1350 · 9 = 12150 (121,50 €), плашка показана (9 > 7). При `age` = 22 вердикт Q3 заменяется «данных мало».
- **Импорт.** Выписка из 152 строк: распознано 138, отклонено 2, дубликатов 12 (138 + 2 + 12 = 152, REQ-092). Ключ для (`acc_bank`, 2026-10-03, −4730, EUR, `k` = 0) — `f78f01e9751c5f66`; две покупки «Cafe Central» по −450 за день дают разные ключи (`k` = 0 → `9d82db80ee854a7c`, `k` = 1 → `b9f6b8bb563b3b40`). Повторный импорт того же файла создаёт 0 записей ([TST-42, TST-43](../product/11-testing-strategy.md)).

## Ловушки и нюансы

1. **Прогноз хорош ровно настолько, насколько полон ввод.** Ни импорт, ни правила не заменяют сверку с банком; плашка «не учтено» — оценка по прошлым расхождениям, не знание.
2. **Расхождение не прячется.** `drift` между якорем и суммой проведённых операций показывается пользователю, а не «подгоняется».
3. **Одинаковые покупки.** Без номера `k` две чашки кофе за 4,50 € в один день слились бы в одну; смена описания банком — «возможный двойник», решение за пользователем. Известная граница (C-047): если во втором файле видна только одна из двух одинаковых операций (`k = 0`), она принимается за дубликат первой — это ограничение не скрывается ([RISK-17](../product/12-risks.md)).
4. **Формулы в ячейках.** При экспорте текстовые поля, начинающиеся с `=`, `+`, `-`, `@`, TAB или CR, экранируются, а числовые колонки не трогаются: иначе ломаются отрицательные суммы. Встроенный профиль `runway-csv/1` при импорте снимает ведущий `'` (только для экспорта самого Runway; C-045).
5. **Агрегаторы региональны и хрупки.** Провайдеры привязаны к регионам, один из них закрылся для новых клиентов, доступ к данным банков бывает платным (таблица выше) — поэтому они вне ядра.
6. **Скорость ввода — гипотеза.** Цель: факт за три поля и три действия, медиана до 5 секунд; публично не обещается до измерения (REQ-090).
7. **Банковский импорт не вводит планы.** Обязательства, резервы, налоговый конверт и часы остаются данными пользователя (вывод); налоговые числа — расчёт по введённым правилам, не консультация.
