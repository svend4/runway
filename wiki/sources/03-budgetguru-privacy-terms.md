# Источник 03: политика и условия Budget Guru

> Страница описывает **источник**: что оператор написал о данных и правилах, что из этого проверено и как это повлияло на проект. Досье — [raw/03](../../raw/03-budgetguru-privacy-terms.md) с разделом «Поправки (errata)». Это самый информативный из трёх документов о Budget Guru: по нему видна заявленная архитектура ([разбор](../tools/budget-guru.md)). Но тексты оператора — **заявления**: приложение за регистрацией не открывалось, реальное поведение не проверялось. Юридических выводов страница не делает; это не консультация.

## Политика конфиденциальности: утверждения и статус

Метки: *текст* — страница прочитана и совпала с досье (это «сказано», не «работает»); *не проверено* — проверить без регистрации нельзя.

| Тема | Что сказано | Статус |
|---|---|---|
| Хранение | введённые вручную счета, остатки, операции, статьи бюджета, часы, налоговые правила и инвойсы лежат в Supabase | текст; бэкапы, регион и шифрование не названы |
| Изоляция | фильтрация по id пользователя внутри базы (RLS); админ-доступ только у разработчика, для поддержки или по запросу | текст; корректность политик RLS не проверить |
| Вход | email и пароль через Supabase Auth, пароль хэшируется | текст |
| ИИ | вопрос и «снимок цифр» идут на сервер, оттуда в Claude через коммерческий API Anthropic; ключ не в браузере; сервис историю диалога не хранит | текст; поведение не проверено; у провайдера данные хранятся ограниченное время для мониторинга злоупотреблений, срок политикой не назван |
| Аналитика | Vercel Web Analytics, по умолчанию без cookies | текст |
| Обратная связь | текст и вложение сохраняются в базе, видит разработчик | текст |
| Права | копия, исправление, удаление, экспорт — по запросу: Telegram-бот, форма в приложении или email; кнопки удаления нет; удаление обычно до 72 часов | текст; кнопка экспорта в приложении (не подтверждено) |

## Условия использования: утверждения и статус

| Тема | Что сказано | Статус |
|---|---|---|
| Стадия | ранний доступ, «как есть», без SLA; не держать единственную копию важных цифр здесь | текст |
| Рамка | не финансовый советник; расчёт по введённым данным; ответы ассистента справочные; 100 % точность прогноза не гарантируется | текст |
| Запреты | спам форм, парсинг и нагрузка скриптами, обход защиты базы, реверс-инжиниринг и поиск уязвимостей не ради сообщения о них | скрейпинг запрещён прямо; объект «реверс-инжиниринг» грамматически не назван, поэтому ни общий запрет, ни его отсутствие утверждать нельзя |
| Изменения | о существенных (например, платный доступ) обещано написать отдельно; канал не указан | текст |
| Третьи стороны | Supabase, Vercel, Anthropic API | текст |

## Поправки по итогам второго прохода

| Было в конспекте | Стало |
|---|---|
| каналы запросов: бот или email | бот, форма в приложении и email |
| запрещён реверс-инжиниринг | формулировка неоднозначна (см. таблицу условий) |
| аналитика без cookies | «по умолчанию» без cookies |
| история диалога не хранится | это про сам сервис; у провайдера есть ограниченное хранение для борьбы со злоупотреблениями |
| об изменениях условий — лично | «написать отдельно», канал не указан |

## Статус проверки

- **Подтверждено как текст:** дата 2026-09-24, Supabase, RLS и Auth, путь к Claude через серверную функцию, Vercel Analytics, срок 72 часа, отсутствие кнопки удаления, «как есть» и отсутствие SLA.
- **Не проверено:** правильность RLS, бэкапы и тариф базы, регион данных, сквозное шифрование, режим без хранения у провайдера модели, юрлицо и юрисдикция оператора.
- **Внешний контекст** (документация Supabase, сроки хранения у провайдера модели, Vercel, статья 12 GDPR) собран на [странице инструмента](../tools/budget-guru.md#данные-и-приватность) и здесь не повторяется.

## Выводы для проектирования (вывод)

| Факт источника | Вывод | Решение Runway |
|---|---|---|
| «Приватность» = нет банковских API, данные лежат в облачной базе | формулировку о данных «только у вас» читать с поправкой | v1 без аккаунтов и сервера; таблица «что где лежит» ([REQ-120](../product/02-requirements.md), [REQ-121](../product/02-requirements.md), [ADR-005](../decisions/adr-005-local-first-optional-sync.md)) |
| Снимок цифр уходит провайдеру без выбора пользователя | паттерн «движок считает, модель озвучивает» полезен как референс, но нужна проверка чисел | v1: ассистент `A0` без LLM, числа подставляет рендерер, верификатор в тестах ([ADR-010](../decisions/adr-010-ai-tools-and-number-verifier.md)) |
| Экспорт и удаление по запросу, кнопки нет | пробел UX; GDPR требует ответа в срок и не требует кнопки (вывод, не юридическая консультация) | кнопки экспорта JSON, CSV, hledger и удаления на устройстве ([REQ-094](../product/02-requirements.md), [REQ-098](../product/02-requirements.md)) |
| Не советник, точность не гарантируется | юридическая рамка сильна и годится как образец | запрет лозунгов вроде «прогноз точен» ([видение](../product/00-vision.md)), юридическое ревью до беты ([REQ-183](../product/02-requirements.md)) |
| «Не храните единственную копию» | бета без надёжных копий | файл-копия как часть ядра ([ADR-005](../decisions/adr-005-local-first-optional-sync.md)) |
| Скрейпинг и нагрузка скриптами запрещены | правило соблюдено | аккаунты не создавались, формы не отправлялись, приложение не скрейпилось ([CLAUDE.md](../../CLAUDE.md), раздел 7) |

### Не в v1

Облачные режимы ассистента (`A1`–`A3`) с отдельным согласием и предпросмотром передаваемых данных, а также зашифрованная синхронизация — v2; в v1 данные никуда не уходят ([ADR-010](../decisions/adr-010-ai-tools-and-number-verifier.md), [ADR-005](../decisions/adr-005-local-first-optional-sync.md)).
