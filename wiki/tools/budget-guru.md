# Budget Guru

## Кратко

Веб-трекер кэшфлоу для фрилансеров и релокантов (RU/EN/ES): ручной ввод, прогноз остатка, проверка покупки, AI-помощник. Публичная бета без SLA.

| Параметр | Значение |
|---|---|
| Автор | один разработчик: на лендинге — Andrey, в статье Т—Ж и контактах — Salkov |
| Код | закрыт (вывод): репозиторий и API на лендинге, в политике и условиях не упомянуты; подробности поиска — ниже |
| Цена | бесплатно в раннем доступе; платных тарифов не опубликовано ([лендинг](https://budgetguru.es/en/), 2026-10-04). О платном доступе обещано написать отдельно, канал не указан ([terms](https://budgetguru.es/en/terms)) |
| «3-дневный триал» | FAQ на EN, RU и ES (2026-10-04) добавляет «без скрытых платежей после 3-дневного триала»; смысл неясен: есть ли триал и что после него. В досье [raw/02](../../raw/02-budgetguru-landing.md) фраза потеряна |
| Запреты в Terms | обход защиты БД, реверс-инжиниринг, поиск уязвимостей «не для сообщения о них», скрейпинг (неоднозначность формулировки — в таблице расхождений ниже) |

**Почему «код закрыт» — вывод.**

- Репозиторий и API в документах продукта не упомянуты.
- Поиск GitHub (API, «budgetguru») дал только однофамильные проекты (Svelte, Rails, Android и др.), не связанные с budgetguru.es; число найденных репозиториев растёт: 19 при первой проверке, 30 при повторной 2026-10-04.
- Запрос «budgetguru.es» — 0 результатов.
- Репозиторий под другим именем поиск не исключает — не подтверждено окончательно.

**Что подтверждено.**

- Функции прогноза — только заявления: приложение за регистрацией, не открывалось. На лендинге слова «demo» нет, но автор в посте Т—Ж пишет, что «открыл демо-режим для тестов» (ссылка и содержимое не проверены).
- Косвенно функции видны на скриншотах лендинга ([dashboard](https://budgetguru.es/images/en/dashboard.png), [afford](https://budgetguru.es/images/en/afford.png); просмотрены напрямую 2026-10-04). Это маркетинговая картинка, а не проверка расчётов.
  - «Обзор» с вкладками Balance / Plan-actual / Analytics / Structure, график со «ступенькой», предупреждения, блок «Payment waves».
  - Меню Accounts / Transactions / Overview / Budget / Taxes / Time.
  - На дашборде также алерт «недоработка 8 ч» и счёт с лимитом (демо-данные, дата 22 сентября 2026).
- Независимо подтверждены свойства компонентов стека (см. «Данные и приватность»), не продукта.

**Независимые отзывы.**

- Независимых обзоров в изученных материалах (2026-10-04) не найдено; поиск неполный:
  - Bing без упоминаний; выдача Habr не отрисовалась; Product Hunt без совпадений; поиск vc.ru — 404;
  - DuckDuckGo и Reddit недоступны; лимит WebSearch исчерпан.
- Внешняя реакция в изученных материалах — 13 комментариев под [постом на Т—Ж](https://t-j.ru/kak-ia-peresobral-svoiu-sistemu-ucheta/) (число подтверждено 2026-10-04): упрёки в саморекламе, замечание модератора, «в Google Sheets можно так же». Страница показывает отдельно «+6» и «+4»; трактовка «6 за / 4 против» не подтверждена.

## Три вопроса

| Вопрос | Поддержка | Как именно |
|---|---|---|
| Q1 Хватит ли к дате? | Заявлено | График остатка с «лесенкой», алерты в «Обзоре»; на лендинге горизонт, шаг, метод не показаны; в статье автора — график ликвидности на 1–6 месяцев вперёд (заявление) |
| Q2 Волна платежей | Заявлено | Платежи «собираются в кластеры», видно «сколько нужно к волне»; правило не раскрыто |
| Q3 Могу ли купить? | Заявлено | Дата + сумма → вердикт и узкая точка: в тексте лендинга €300 → «Да, спокойно», минимум €7 600; на скриншоте лендинга та же цифра €7 600 стоит у покупки 120 EUR (7 720 − 120), т.е. источник себе противоречит |
| Редкие траты | Заявлено только в статье | Годовые платежи делятся на ежемесячные резервы; на лендинге — лишь «разовые» статьи и план с/без единоразовых |
| Налоги | Заявлено | «Правила по датам»; в статье — конверт 20% с €3000 (иллюстрация). Расчёт по введённым правилам, не консультация |

## Как это устроено

1. **Ввод.** Только вручную: счета (деньги/активы/долги), операции, статьи бюджета, часы, налоговые правила, инвойсы (политика). Старт с нуля, импорта нет.
2. **Движок** (вывод): события с датой, суммой, валютой и фактическим курсом → детерминированная траектория остатка; платежи группируются в «волны» (алгоритм неизвестен).
3. **Q3** (вывод): гипотетическая покупка — дельта к траектории; результат — минимум остатка и его дата.
4. **AI:** вопрос + «снимок цифр» → серверная функция → Claude через Anthropic API; ключ не в браузере ([privacy](https://budgetguru.es/en/privacy)). Числа считает движок, LLM их озвучивает (заявлено).
5. **Стек** (вывод): Supabase (Postgres, RLS, Auth), Vercel (Web Analytics; хостинг — вывод), тип серверной функции неизвестен. По посту автора на Т—Ж: React, Vite, Supabase, Vitest, Claude Code (подтверждено 2026-10-04; Claude Code — инструмент разработки, не рантайм-компонент (вывод)).
6. **Клиент:** веб-приложение с установкой на домашний экран; офлайн не заявлен.

## Сильные стороны

- Чёткая формулировка трёх вопросов и честный блок «чего здесь нет».
- Паттерн «детерминированный расчёт → снимок → LLM», зафиксированный даже в политике.
- Ручной ввод как осознанное решение, без банковских агрегаторов.

## Данные и приватность

| Тема | Факт | Проверка |
|---|---|---|
| Хранение | Supabase, RLS; админ-доступ у разработчика | Docs: таблица в открытой схеме без RLS читается и пишется любой ролью с грантом ([docs](https://supabase.com/docs/guides/database/postgres/row-level-security)); включён ли RLS по умолчанию, страница не говорит (не подтверждено); корректность политик извне не проверить |
| Бэкапы | в политике не упомянуты | Free-план Supabase без бэкапов, пауза через неделю простоя ([pricing](https://supabase.com/pricing)); план неизвестен |
| AI | «снимок цифр» уходит в Anthropic; политика: сервис историю диалога не хранит, у провайдера данные хранятся «ограниченное время» только для мониторинга злоупотреблений (срок не назван) | Без обучения по умолчанию, кроме явного opt-in и отправленного фидбека ([Anthropic](https://privacy.claude.com/en/articles/7996868-is-my-data-used-for-model-training)); срок хранения у Anthropic — список ниже; использует ли Budget Guru zero-retention, неизвестно |
| Аналитика | Vercel Web Analytics, «по умолчанию» без cookies | Vercel: без third-party cookies, посетитель — хэш запроса, сессия сбрасывается через 24 ч ([Vercel](https://vercel.com/docs/analytics/privacy-policy)); про first-party cookies доки молчат |
| Права | доступ, исправление, экспорт, удаление — по запросу (Telegram-бот, форма обратной связи в приложении, email), удаление «обычно до 72 ч»; кнопки удаления нет | GDPR требует ответа за месяц (продление до трёх) и не требует кнопки ([ст. 12](https://gdpr-info.eu/art-12-gdpr/)) — это пробел UX, не обязательно закона (вывод; не юр. консультация) |

Хранение API-данных у Anthropic (страница от 2026-07-01, [retention](https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-my-organization-s-data)):

- удаляются в течение 30 суток;
- при срабатывании Usage Policy — входы/выходы до 2 лет, оценки классификаторов до 7 лет;
- возможны юридические исключения.

Self-host нет. «Приватность» здесь означает отсутствие банковских API, а не «данные только у вас»:

- лендинг (RU, 2026-10-04) говорит «Ввод только вручную — финансы остаются только вашими» (в контексте отсутствия доступа к картам и банковским API) и «счета не оказываются ни в одном стороннем сервисе, кроме вашего собственного»;
- политика же называет Supabase и Anthropic API — внутреннее противоречие самого продукта (вывод).

## Что взять в Runway

- **Снимок для LLM:** движок отдаёт типизированный JSON (остатки, `min_point{date, amount_minor}`, волны); постфактум проверка — каждое число ответа обязано быть в снимке.
- **Q3 как вердикт:** `min(balance[t])` + дата + буфер в minor units; у Runway один словарь из четырёх классов `OK` / `TIGHT` / `FRAGILE` / `NO` (решение C2 канона, [ADR-006](../decisions/adr-006-forecast-semantics.md)).
- **План «с/без единоразовых»:** два прогона одного движка как базовые сценарии.
- **Страница «чего нет»** со статусами заявлено / сделано / в планах — публичный roadmap.
- **Демо без регистрации** на синтетических данных: проверяемость вместо обещаний.
- **Golden-тесты движка** на обезличенных кейсах: рефакторинг с ИИ не меняет арифметику.

## Чего избегать

- Сравнения только с выбранными конкурентами и критериями: матрица Runway полная, с `none` и `unknown`.
- «Приватность» без E2E и local-first при админ-доступе и передаче цифр в LLM — нужна оговорка или архитектура.
- Экспорт и удаление «по запросу»: с первого релиза self-service JSON/CSV и delete-all.
- Бета без импорта и бэкапов с советом «не храните единственную копию».
- Двусмысленная цена и абсолютные обещания «без галлюцинаций» — формулировать как проверяемые инварианты.
