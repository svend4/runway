Автор: FP-07 (сценарии, правки волн и «почему» у каждого числа). Дата: 2026-10-05. Код — `prototype/demo/` (`pack_fp07.mjs`, `scenario_builder.mjs`, `wave_edit.mjs`, `why_more.mjs`, `i18n/scenarios.mjs`, `css/scenarios.css`) и `prototype/engine/` (`scenario_ext.mjs`, `wave_sweep.mjs`), тесты — `prototype/tests/scenario_builder.test.mjs`, `wave_edit.test.mjs`, `why_more.test.mjs` (18 + 12 + 12).
Общие файлы (`app.mjs`, `i18n.mjs`, `index.html`, `style.css`, `ext.mjs`, `ws_edit.mjs`, `tests/demo.test.mjs`) пакет не правил: всё, что нужно, подключено через уже существующие слоты и хуки `waves.actions`, `overview.cards`, `show_why`, `scenario_ops` и собственный экран `#scenario_lab` («Конструктор»).

## 1. FP-01 / интегратор (`demo/app.mjs`): три небольшие правки, которые делают пакет заметнее

Пакет работает и без них; с ними блоки стоят там, где пользователь их ждёт.

1. **Штатная таблица «Из чего сложилась просадка» (`show_why`)** показывает только группы цепочки до `explain.share_cutoff_bp` и поэтому не доходит до просадки (G-001, «если хуже»: 200000 против 217000). Пакет уже добавляет в диалог второй блок «Полная цепочка: все строки до итога» с «Остальное» и словесной сверкой. Чтобы в самой таблице приложения не было расхождения, достаточно добавить в `explain_model` две строки (данные есть в ответе `explain_narrowest`):

   ```js
   const rest = ex.out_total_minor - ex.chain.reduce((s, g) => s + g.amount_minor, 0);   // «Остальное»
   // inflow = ex.inflow_offset_minor                                                      // «Поступления в окне (−)»
   ```

   и две строки в `chain_rows` (`wy.rest`, `wy.inflow`; итоговая строка — просадка). После этого блок пакета в `show_why` можно убрать из `register` (`pack_fp07.mjs`, одна строка).
2. **Экран «Могу ли я это купить?», строка «по плану»** (`render_buy_result`): `why_button` стоит только у «если хуже» (`m === 'worse' ? [' ', why_button('worse')] : null`). Просьба: `why_button(m)` у обеих строк (REQ-104: «почему» у вердикта в обоих режимах). Пока запрос не принят, «почему» у вердикта по плану — в карточке «Почему так» на «Обзоре» (кнопка «Почему вердикт по плану»).
3. **Слот в экране «Сценарии»**: `SLOTS` в `ext.mjs` не содержит места на экране «Сценарии», поэтому конструктор вынесен на свой экран `#scenario_lab` (пункт «Конструктор» в навигации, после «Сценариев»). Предложение: слот `scenarios.after` в конце `view_scenarios` (один вызов `...ext.slot_nodes('scenarios.after')`), тогда `render_lab` можно зарегистрировать и там; сохранённые конструктором сценарии уже видны на экране «Сценарии» как сохранённые (`ws.scenarios` → чипы).

Необязательно: слот `waves.card` (аргумент — волна) внутри `section.wave-card`, чтобы кнопки «Почему вместе?», «Почему такая потребность» и «Объединить с волной N» стояли прямо на карточке волны. Сейчас они в блоке «Правки волн» (слот `waves.actions`) под календарём — это тот же код, `render_wave_edit` делит блок по волнам.

Хук `scenario_ops` зарегистрирован и понимает виды `fx {currency, bp}`, `shift {event_ref, days}`, `hours {stream_id, minutes}` и `ops {ops}`: если приложение добавит чипы с такими описаниями в `add_scenario`, они сразу считаются (`hours` разворачивается в `set_amount` через `engine/scenario_ext.mjs`). Нужна ещё функция имени сценария для чужих видов (`scenario_name` для неизвестного вида возвращает пустое имя, как для `saved` без идентификатора): либо хук `scenario_name`, либо поле `label` в описании сценария.

## 2. FP-01 (`demo/ws_edit.mjs`): два вопроса по видам правок

1. `set_wave_override` отвергает `event_ids = []` (`one_to_200_ids`) даже у `pin` с `pin_range`. Пакет обходит это: «закрепить даты» записывает платежи диапазона перечнем и `pin_range` рядом (`plan_pin_range`). Если нужна запись «только диапазон» (правка переживает появление новых платежей в диапазоне), у `pin` стоит разрешить пустой перечень при заданном диапазоне; код движка (`apply_wave_overrides_ex`) это уже умеет.
2. `save_scenario` проверяет операции по списку `SCENARIO_OPS` (семь операций v1, без `hours`), поэтому сценарий с «часами» в набор не сохраняется — это намеренно: канон (`apply_scenario` → `E_SCHEMA op_not_in_v1`) относит `hours` к v1.1. Конструктор говорит об этом словами и оставляет такой сценарий гипотезой на экране. Решение владельца: разрешать ли хранение `hours` (тогда `check_op` вызывает `validate_hours_op`, а страница считает сценарии через `analyze_ext`).

Оба файла `engine/` вне карты слоёв §14 B4 (импортируют `index`/`timeline`/`waves`; на них никто не ссылается) — `purity.test.mjs` их проверяет на чистоту и циклы, как остальные.
- `_ops/tst-coverage.json`: пересобрать — в названиях новых тестов есть TST-27, TST-33, TST-37, TST-58 и REQ-036, REQ-049, REQ-050, REQ-051, REQ-104.
- `wiki/algorithms/alg-02-timeline-projection.md`, `wiki/product/02-requirements.md` (REQ-051): записать смысл операции `hours{stream_id, minutes, from?, to?}` как он реализован: `minutes` — ожидаемые минуты каждого периода потока (вместо `hours.exp_minutes` и `hours_by_period`), `min/max` периода подтягиваются, чтобы `min ≤ exp ≤ max`; период, закрытый с фактом (`actual_minutes`), не меняется; `from`/`to` — границы по началу периода; операции `hours` переводятся в начало списка и разворачиваются в `set_amount` над событиями потока, которые есть в модели; режим `worse` часы сам не включает. Критерий REQ-051 «доход октября 240000 вместо 279000 (80 ч вместо 93 ч)» проверен на G-001 (`S-HOURLY@2026-11-05`).
- `wiki/algorithms/alg-03-payment-waves-detection.md` (REQ-036): правки волн хранятся с идентификатором по содержимому `wov_<12 hex>` (одна и та же правка → один идентификатор → повтор ничего не пишет, идемпотентность); `merge` ссылается на первые платежи двух волн, `split` — на платёж, перед которым режет, `pin` — на платежи (и диапазон дат).
- Критерий TST-33 говорит о «`facts_hash`»: такой функции в движке нет. Тест считает хэш содержимого `ws.facts` и записей `tx.posted` журнала (номера записей `seq` при добавлении сценария сдвигаются, содержимое фактов — нет). Если нужен именованный `facts_hash`, его место — `engine/ledger.mjs` (FP-02).

## 4. Заметки для авторов других пакетов

- `Element.replaceChildren(...)` и `append(...)` в браузере превращают `null` в текст «null», а `h(...)` из `dom.mjs` его пропускает: в `replaceChildren` передавайте только узлы (фильтруйте `null`).
- Сообщение «Сохранено» после записи: страница перерисовывается **внутри** `ctx.edit`, поэтому флаг сообщения ставится до вызова и снимается при отказе (так сделано в `wave_edit.mjs` и `scenario_builder.mjs`).
- «База» для сравнения сценариев — данные без включённого на странице сценария: конструктор при включённом сценарии считает базу отдельно (`analyze(ws)`), а не берёт `get_model().ctx`.
