# Запросы FP-03 к владельцам общих файлов

Автор: FP-03 (настройки, буфер, запас хода, честная готовность данных). Дата: 2026-10-05. Код — `prototype/demo/` (`settings.mjs`, `home_cards.mjs`, `number_format.mjs`, `pack_fp03.mjs`, `i18n/settings.mjs`, `css/settings.css`), тесты — `prototype/tests/settings.test.mjs`, `settings_boot.test.mjs`.
Общие файлы (`app.mjs`, `i18n.mjs`, `index.html`, `style.css`, `ext.mjs`, `tests/demo.test.mjs`, `tests/ext_boot.test.mjs`) пакет не правил.

## 1. FP-01 / интегратор (`demo/app.mjs`, `demo/ext.mjs`): формат чисел и дат отдельно от языка (REQ-112)

Пакет умеет всё, кроме одного: `fmt()` приложения (`make_fmt(lang, cur, as_of_iso)`) по-прежнему берёт числа и даты от языка, поэтому настройка `ws.number_format` действует на экране «Настройки» и в карточках FP-03, но не на остальных экранах. `make_nf_fmt(lang, cur, as_of_iso, nf)` из `demo/number_format.mjs` — тот же набор (`money`, `money0`, `date`, `short`, `pm`, `bp`, `days`, `exp`) и без настройки равен `make_fmt` (тест `settings.test.mjs`, «без настройки make_nf_fmt равен make_fmt»). Два способа подключить:

- **Через хук (предпочтительно: `app.mjs` не знает пакеты).** В `ext.mjs` добавить имя хука `fmt` в `HOOKS`; в `app.mjs` заменить определение форматтера:

  ```js
  const fmt = () => ext.first('fmt', S.lang, S.model.cur, S.model.as_of_iso, S.ws?.number_format) ?? make_fmt(S.lang, S.model.cur, S.model.as_of_iso);
  ```

  (строк с обращением к `ext` останется не больше 40). После этого пакет FP-03 регистрирует хук одной строкой в `pack_fp03.mjs` — напишите мне или добавьте сами:

  ```js
  ext.register_hook('fmt', (ctx, lang, cur, as_of, nf) => (nf === undefined || nf === null ? undefined : make_nf_fmt(lang, cur, as_of, nf)));
  ```

- **Напрямую:** импортировать `make_nf_fmt` в `app.mjs` и вызвать с `S.ws?.number_format`; тогда в `tests/demo.test.mjs` меняется список импортов `app.mjs` (`['../engine/index.mjs', '../engine/tools.mjs', '../engine/verifier.mjs', './ext.mjs', './i18n.mjs']`).

Что не меняется и должно остаться так: ассистент A0, верификатор и шаблоны (`render_value`, `extract_quantities`) работают по языку интерфейса — числа в ответе сверяются с `evidence` в формате языка. Это записано в тексте экрана («Тексты ассистента строятся по языку интерфейса»). Поля ввода других пакетов должны разбирать суммы через `parse_amount_text(text, cur, lang, ws.number_format)` (строгий разбор по формату, TST-51).

## 2. FP-01 / интегратор (`demo/app.mjs`, `view_overview`): слот карточек при `s < ready.q1`

При готовности данных меньше `ready.q1` (3) `view_overview` возвращает `ov.empty` до отрисовки слота `overview.cards`, поэтому карточка «Готовность данных» с перечнем недостающего (`readiness.reasons`) именно там, где она нужнее всего, не видна. Просьба: в ранней ветке добавить слот перед `return root`:

```js
if (a.readiness.score < (a.params['ready.q1'] ?? 3)) {
  root.append(h('p', { class: 'banner', role: 'status', text: tr('ov.empty') }), ...ext.slot_nodes('overview.cards'));
  return root;
}
```

Карточка «Запас хода» при `s < ready.q1` числа не показывает (пояснение «появится вместе с прогнозом»): запас хода по пустым данным выглядел бы как «хватает на весь горизонт». Пока запрос не принят, список недостающего доступен на экране «Настройки» (карточка в конце экрана) — он открывается из навигации при любой готовности.

## 3. FP-01 / интегратор (`demo/app.mjs`, `demo/i18n.mjs`): плашка «Не учтено: повседневные траты» не зависит от причины

`render_summary` показывает `banner.not_ready` («Не учтено: повседневные траты.») при любом `s < ready.q3`, а `gate.readiness` называет ту же причину («не задана оценка повседневных трат»). При `no_account`, `obligations_lt_3` или `no_income_45d` текст неверен: движок называет другую причину. Просьба (любой из вариантов):

- убрать плашку из шапки и ключ `banner.not_ready` (при удалении ключа тест TST-56 «нет мёртвых ключей» требует убрать и его использование) — карточка FP-03 на «Обзоре» и в «Настройках» строится из `readiness.reasons` и называет каждую причину своим текстом;
- либо заменить текст плашки перечнем по `a.readiness.reasons` (ключи пакета `settings.rd_miss_<причина>` готовы, функция `miss_key(reason)` — в `demo/home_cards.mjs`), а `gate.readiness` заменить на нейтральное «готовность данных ниже порога: посмотрите, что не учтено» (то же самое делает `settings.gt_readiness` для карточки).

## 4. Интегратор (`tests/ext_boot.test.mjs`)

Тест `boot: … навигация построена из реестра …` сравнивает список ссылок навигации точно. С файлом `pack_fp03.mjs` (экран `#settings`, `order` 85) список получает `'#settings'` последним, после `'#data'` — тест падает (одна проверка, остальные 21 тест файла проходят). Нужно либо ожидать пакетные экраны по `ext.nav_items()`, либо проверять префикс списка. Аналогично будут вести себя экраны остальных пакетов.

## 5. Координатор: канон и документы

- **`Workspace.number_format`** (design-brief §3.1, `04-data-model.md`): в каноне сказано только «отдельная настройка». В прототипе принято: `number_format = {decimal?, thousands?, date?}`; `decimal ∈ {',', '.'}` и `thousands ∈ {'', ' ', ',', '.'}` задаются только парой и не совпадают; `date ∈ {auto, iso, dmy, mdy}` (`auto` в данные не пишется); пусто — «по языку» (ключа нет). Хранится ключом рабочей области, в журнале — в служебном профиле `ws:meta` (проверено: круг `ws → журнал → ws` и снятие настройки, `settings.test.mjs`). Вид правки — `set_number_format` (регистрируется пакетом; `ws_edit.mjs` его не знает). Просьба внести форму в §3.1 и в `validate_ws` (сейчас неизвестный верхний ключ принимается как есть; недопустимое значение из чужого файла безопасно: показ возвращается к формату языка, `sanitize_number_format`).
- **`PARAM_SPECS['wave.threshold_minor']`** (FP-01, `ws_edit.mjs`): `min: 0`, а канон требует `θ ≥ 1`. Сейчас запись 0 принимает `set_param`, а отказывает пересчёт страницы (`E_SCHEMA`) — данные не меняются и форма показывает причину (тест `settings.test.mjs`, «отказ записи»), но проверка должна стоять на уровне правки: `min: 1`.
- **`wiki/product/15-prototype-guide.md`, `prototype/README.md`** (карта модулей и каталога): `demo/settings.mjs`, `home_cards.mjs`, `number_format.mjs`, `pack_fp03.mjs`, `i18n/settings.mjs`, `css/settings.css`; тесты `settings.test.mjs` (35), `settings_boot.test.mjs` (6). Число тестов после общего прогона пересчитать. Раздел «Демо»: добавлен экран «Настройки» и две карточки «Обзора»; в «Ограничениях» изменить «нет форм для счетов, правил и фактов» нельзя (форм по-прежнему нет — это FP-04/FP-08), но «Нет настроек в демо» теперь неверно.
- **`_ops/tst-coverage.json`**: пересобрать — в названиях тестов FP-03 есть TST-09, 12, 35, 51, 56, 57, 58, 59 и REQ-012, 017, 023, 024, 025, 026, 029, 112.
- **`_ops/gap/backlog.json` (FP-03)**: в `new_files` нет `demo/pack_fp03.mjs` — файл создан (точка входа пакета, манифест его ждёт); `index.html` не правился: стили подключает `ext.ensure_css('css/settings.css')`.
- **Каталог `demo/i18n/settings.mjs`**: названия ступеней готовности (`rd_level_*`: «пусто», «каркас», «рабочая», «почти полная», «полная») придуманы в этом пакете — в каноне уровни названы только английскими идентификаторами (`empty … full`), русские подписи вики не фиксирует; REQ-029 называет только «полный».

## 6. Не запросы (заметки для других пакетов)

- Экран и карточки FP-03 читают модель через `ctx.get_model()` и форматируют числа через `make_nf_fmt(ctx.lang(), model.cur, model.as_of_iso, ws.number_format)`; другим пакетам, которым нужны числа в формате пользователя уже сейчас, достаточно того же вызова.
- Пакет, который пишет несколько параметров за раз, делает так же, как `settings.mjs → save_edits`: цикл `apply_edit` и один `ctx.set_ws` (один пересчёт, одна запись журнала на группу).
- Расчёт по введённым данным и правилам, не консультация.
