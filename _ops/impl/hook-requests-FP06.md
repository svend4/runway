# Запросы FP-06 к владельцам общих файлов

Автор: FP-06 (мастер импорта CSV и hledger, сухой прогон, откат партии). Дата: 2026-10-05. Код — `prototype/demo/` (`import_model.mjs`, `import_wizard.mjs`, `pack_fp06.mjs`, `i18n/import.mjs`, `css/import.css`), данные — `prototype/data/profiles/*.json`, тесты — `prototype/tests/import_model.test.mjs`, `import_wizard.test.mjs`, образец — `tests/fixtures/import-152.csv`.
Общие файлы (`app.mjs`, `i18n.mjs`, `index.html`, `style.css`, `ext.mjs`, `tests/demo.test.mjs`) пакет не правил: мастер подключается слотом `data.sections` через `register(ext)`.

## 1. Интегратор (`tests/demo.test.mjs`, TST-56): имя пространства строк `import` совпадает с именами типов записей журнала

Проверка «каждый литерал `'пространство.имя'` в коде демо — существующий ключ строки» принимает за ключ и тип записи журнала `'import.started'` из `demo/journal_log.mjs` (строка 80; рядом `'import.rolled_back'`). Пространство `import` задано именем файла `i18n/import.mjs` (по заданию FP-06), поэтому пакет добавил в каталог ключи `import.started` («Файл принят: …», используется мастером при приёме файла) и `import.rolled_back` («Партия … откатена», тоже используется). Тест зелёный, но совпадение случайное. Просьба (необязательная): в проверке исключать литералы из `journal_log.mjs` (или список типов записей журнала), тогда ключ `import.started` можно переименовать без последствий.

## 2. Интегратор: расхождение, не относящееся к FP-06

- `tests/ext_boot.test.mjs`, тест «смена набора данных (ext.reset): журнал пересобирается, подписчики получают adopt»: список причин подписчика теперь содержит ещё две записи `fp05_refresh` (подписка пакета FP-05). Тест ждёт ровно `['adopt']`; правка теста — за FP-05/интегратором (пакет FP-06 в этом тесте причин не добавляет: его подписка реагирует только на `adopt` и сама ничего не записывает).
- `tests/demo.test.mjs`, TST-56 «запрещённые формулировки §10»: подстрока «безопасно» найдена в `demo/pack_fp05.mjs` (строка 16, «Безопасно прочитать…») и в комментарии `demo/data_view.mjs` (строка 3, «Безопасность: …»). Файлы FP-06 эту проверку проходят.

## 3. Интегратор: запись мастера и стопка «Отменить / Вернуть» (FP-04)

Мастер пишет партию одним `ctx.set_ws(ws, {reason: 'import'})`, откат — `{reason: 'import_rollback'}`. Стопка отмены FP-04 их не знает: кнопка «Отменить» отменяет только собственные единицы FP-04. Откат партии для пользователя — кнопка «Откатить партию» (шаг «Готово» и список «Партии импорта» на экране «Данные»). Если интегратор захочет единую стопку, подписка на `reason === 'import'` в `pack_fp04.mjs` может поставить на стопку единицу «партия импорта» с `rollback_batch` из `import_model.mjs`.

## 4. Что мастер не переносит (честные границы, чтобы не казалось «молчаливой потерей»)

- hledger: периодические правила `~` и разовые планы в рабочую область мастером не вносятся; в отчёте строка «Найдено, но не перенесено: …». Цена `@`/`@@` и больше двух активных ног — отказ всего журнала со строкой «не поддержано» и номером строки.
- Сведения о счетах, якорях и курсах, внесённых hledger-партией, живут в памяти вкладки (`w.batches`). После перезагрузки страницы откат партии убирает её факты (они несут `batch_id`), а внесённые партией счета, якоря и курсы остаются; счёт можно убрать вручную.
