# Мониторинг рынка раз в 90 дней и напоминание на 2027-01-02 (REQ-190)

> **Ближайшая проверка: не позже 2027-01-02.** Этот файл — напоминание и шаблон. Сам он никого не оповещает и ничего не проверяет: календарное событие ставит владелец (раздел 2), проверку делает человек.

## 1. Зачем

Позиционирование Runway «автоматический минимум остатка с вердиктом и доход по часам в одном прогнозе у изученных личных инструментов не найден» верно **только на дату проверки**: «в изученных материалах не найдено (2026-10-04)». Если [PocketSmith](../../wiki/tools/pocketsmith.md) или Monarch ([современные SaaS-трекеры](../../wiki/tools/modern-saas-trackers.md)) выпустят автоматический минимум с вердиктом **и** часы в прогнозе, срабатывает критерий остановки № 6 (REQ-181, RISK-10): позиционирование пересматривается. Требование REQ-190: раз в 90 дней проверять их публичные материалы и фиксировать дату проверки.

## 2. Расписание

База проверки — 2026-10-04. Шаг — 90 дней.

| Проверка | Срок (не позже) |
|---|---|
| первая | 2027-01-02 |
| вторая | 2027-04-02 |
| третья | 2027-07-01 |
| четвёртая | 2027-09-29 |

Как поставить напоминание: в календаре владельца — событие на 2027-01-02 с повтором «каждые 90 дней» (если календарь не умеет 90 дней — отдельные события на даты таблицы) и ссылкой на этот файл. Напоминание в приложении не предусмотрено: у Runway нет ни сервера, ни уведомлений.

## 3. Что проверять

Читать публичные материалы **вручную, обычной загрузкой страниц в браузере**: без регистрации, без входа в аккаунты, без скриптов-скрейперов (правила безопасности вики, [CLAUDE.md](../../CLAUDE.md), §7). Начинать с адресов, на которые уже опираются страницы вики (перечислены в их поле `sources`): журнал изменений и страницы «что нового» (у Monarch — `whats-new` и блог о прогнозе), справка о календаре, прогнозе и сценариях (у PocketSmith — раздел справки `learn.pocketsmith.com` про календарь, график прогноза и сценарии), страница функций. Адреса могли измениться: если страница ушла, зафиксировать это и найти замену.

Для каждого из двух продуктов ответить на три вопроса. Ответ «да» требует ссылки и даты доступа; «не найдено» допустимо только вместе с датой.

| № | Вопрос | PocketSmith | Monarch |
|---|---|---|---|
| 1 | Находит ли продукт **автоматически** минимум остатка на горизонте прогноза и показывает его без ручного поиска по графику? | | |
| 2 | Выдаёт ли он по этому минимуму **вердикт** вида «хватит / не хватит» для покупки или для даты? | | |
| 3 | Есть ли в прогнозе **доход по часам** (ставка × отработанные часы), а не только фиксированные поступления? | | |

Срабатывание критерия № 6: по одному из двух продуктов ответы 1 и 2 (авто-минимум с вердиктом) и 3 (часы) — «да» одновременно. Если «да» только на часть — это не срабатывание, но фиксируется в записи как «приблизились».

## 4. Запись о проверке

Запись пишется в журнал вики после каждой проверки (операция `ingest`), даже если ничего не найдено. Из каталога `runway/`:

```text
node tools/log.mjs "ingest | Мониторинг рынка ГГГГ-ММ-ДД: PocketSmith, Monarch" "Проверено ГГГГ-ММ-ДД (REQ-190, критерий № 6). PocketSmith: авто-минимум с вердиктом — не найдено/найдено (<адрес>, доступ ГГГГ-ММ-ДД); часы в прогнозе — не найдено/найдено. Monarch: то же. Срабатывание № 6: нет/да. Следующая проверка не позже ГГГГ-ММ-ДД."
```

Чужие тексты в запись и в вики не копируются: пересказ своими словами, не более одной короткой цитаты (меньше 15 слов) с атрибуцией ([CLAUDE.md](../../CLAUDE.md), §7).

Если ответ противоречит страницам вики: старое не удаляется молча, а помечается в тексте обеих страниц и в записи журнала ([CLAUDE.md](../../CLAUDE.md), раздел «Ingest»). Если критерий № 6 сработал, добавляется запись `decision` по шаблону из [критериев остановки](stop-criteria-record.md), раздел 2.
