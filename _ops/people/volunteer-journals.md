# Журналы добровольцев: инструкция, согласие и анонимизация (REQ-176, REQ-188)

Нужно **не менее 10 журналов** людей, которые вели учёт в Runway (или в совместимом файле), чтобы: (1) выполнить гейт релиза REQ-176 — бэктест вердикта «как знали тогда», FRR не более 5 % и cry-wolf не более 50 % (пороги и окно 30 дней — гипотезы, пока нет замера); (2) откалибровать параметры волн REQ-188 (`wave.gap_days`, `wave.max_span_days`, `wave.threshold_minor`). Без выполненного замера релиз не выпускается. Сейчас журналов добровольцев **нет**: гейт посчитан только на синтетике (`data/backtest-report.json`), и она выбор параметров не доказывает. Этот файл — инструкция и шаблон согласия; ни согласия, ни журналов он не заменяет.

> **Текст согласия (раздел 2) не проходил юридическое ревью.** Его включают в объём ревью по REQ-183 ([пакет для юриста](legal-review-package.md)) до первой рассылки. Расчёт по введённым данным и правилам, не консультация.

## 1. Какой журнал подходит

- Файл-копия формата `runway-journal/1` (кнопка «Скачать журнал» на экране «Данные»), прочитанный приложением без ошибок.
- История не меньше трёх месяцев (в дорожной карте гейт стоит «после 2–3 месяцев истории» — это ориентир, а не требование формата) и хотя бы несколько сверок остатка (якорей): без них нечего сравнивать с прогнозом.
- Реальные платежи и поступления, а не только пример G-001.

## 2. Согласие добровольца (текст для рассылки)

> Я добровольно передаю файл-копию журнала приложения Runway для проверки качества прогноза и настройки параметров приложения.
>
> 1. **Что передаётся.** Только файл, обработанный программой анонимизации: все даты сдвинуты на одно и то же число дней, кратное 7, а суммы умножены на один общий множитель от 0,5 до 2. Названия счетов, платежей и заметки программа не очищает; я просмотрел файл и заменил в нём всё, по чему меня можно узнать.
> 2. **Что остаётся неизменным.** Структура журнала, порядок записей, валюты, дни недели. День месяца у повторяющихся платежей и граница «конец месяца» не сдвигаются: по ним меня теоретически можно узнать, а метрики на анонимизированном файле могут отличаться от настоящих.
> 3. **Чего не передаётся.** Исходный файл, число сдвига дней, множитель, значение seed, моё имя и контакты вместе с файлом.
> 4. **Кто увидит файл.** Владелец проекта: [заполняется — имя и роль]. Файл не публикуется и не передаётся третьим лицам; в публичных отчётах (бэктест, калибровка) приводятся только агрегаты по всем журналам и число журналов.
> 5. **Срок хранения.** [заполняется владельцем — срок не принят]. Я могу в любой момент попросить удалить файл; для этого мне сообщён способ связи: [заполняется].
> 6. **Анонимизация не абсолютна:** по структуре данных человека в принципе можно узнать, и я это понимаю.
> 7. Это помощь проекту, а не платная услуга; приложение не даёт мне финансовых, налоговых или юридических советов.
>
> Дата: ________ Код добровольца (выдаёт владелец): V____ (без подписи именем в файле)

## 3. Инструкция добровольцу

Требуется: Node.js версии 24 или новее и копия каталога `prototype/` проекта (инструмент написан на Node, браузер для него не нужен). Если Node нет, см. вариант Б в разделе 4.

1. **Скачать журнал.** В приложении: «Данные» → «Скачать журнал». Файл сохраняется на вашем устройстве (в приложении он не шифруется: файл читает любой, у кого он есть).
2. **Просмотреть файл** текстовым редактором. Найти названия счетов, платежей, ссылки, заметки и любые слова, по которым вас можно узнать (имена людей, названия компаний, адреса, номера). Заменить на нейтральные («Счёт 1», «Платёж 3»). Поля `id` и формат файла не менять.
3. **Запустить анонимизацию** из каталога `prototype/`:

   ```text
   node tools/anonymize.mjs вход.json выход.json --seed 12345
   ```

   `--seed` — любое целое число, известное только вам: из него выводятся сдвиг дат и множитель. Программа печатает на экран `shift_days` и `k_bp`: **эти числа не отправлять и не сохранять рядом с файлом**; в выходной файл они не записываются. Исходный файл программа не перезаписывает (имена входа и выхода должны отличаться).
4. **Проверка пары «до / после»** (`verify_anonymized`) выполняется программой сама; при расхождении она ничего не пишет и сообщает причину. Предупреждение о днях месяца (`by_monthday`, «конец месяца») — штатное: см. вопрос ADV-6 в разделе 6.
5. **Открыть выходной файл и проверить его глазами:** названия нейтральны, дат в привычном виде нет (все сдвинуты), суммы не совпадают с банковскими. Если что-то узнаётся — исправить и повторить шаг 3 с другим `--seed`.
6. **Передать файл** `выход.json` владельцу способом, который он назвал [канал не выбран — вопрос владельцу, раздел 6]. Исходный файл, seed и числа сдвига остаются у вас.

## 4. Варианты, если у добровольца нет Node

| Вариант | Как | Минус |
|---|---|---|
| А. Доброволец анонимизирует сам | шаги раздела 3 | нужен Node 24 |
| Б. Владелец анонимизирует файл при добровольце (на его устройстве или при личной передаче) и сразу удаляет исходный | доброволец передаёт исходный файл лично, видит запуск и результат | владелец видит исходные данные: нужно особое доверие и запись в согласии |
| В. Анонимизация в приложении | страница для добровольца | **в приложении её нет**; это отдельный пакет (FP-39), он ждёт ответа владельца |

Выбор между А и Б — вопрос владельцу (раздел 6). Вариант Б противоречит духу согласия «исходный файл не передаётся» и должен быть описан в нём прямо.

## 5. Приём и учёт журналов (для владельца)

- Каждый полученный файл проверяется: открывается через `read_journal_json` без ошибок; число записей и период разумны; нет читаемых имён в названиях.
- Файл хранится в каталоге вне репозитория или в `_ops/people/journals/` (создаётся при первом приёме; **в git не добавлять**, пока владелец не решил иначе).
- Учёт без имён:

| Код | Дата согласия | Дата получения | Записей | Период (месяцев) | Правил с днём месяца (`by_monthday`) | Потоков с границей «конец месяца» | Заметка |
|---|---|---|---:|---:|---:|---:|---|
| V01 | | | | | | | |

- Когда накоплено 10 файлов, запускается замер — это отдельный пакет (FP-39). Его критерии: гейт `release_gate` по сумме счётчиков по журналам (`N1 > 0`, `N2 > 0`, FRR ≤ 5 %, cry-wolf ≤ 50 %); значения и дата записываются с `n`. Пока нет решения по ADV-6, гейт **не считать по анонимизированным журналам без сравнения «до / после»**.

## 6. Открытые вопросы владельцу

| № | Вопрос | Варианты |
|---|---|---|
| ADV-6 | Анонимизация сдвигает даты на 7·N дней, но не сдвигает день месяца правил и границу «конец месяца» — метрики бэктеста на анонимизированном журнале могут отличаться от настоящих (тест `fp11_adv`, пометка `todo`). Как с этим быть? | (а) пересчитать календарные поля при анонимизации и честно оговорить остаточное расхождение; (б) самопроверка добровольца: запустить бэктест на исходном и на анонимизированном файле и сообщить расхождение; (в) не использовать анонимизированные журналы для гейта, а считать гейт только по журналам, прошедшим другую процедуру |
| В1 | Кто и каким каналом набирает не менее 10 добровольцев, как передаётся файл? | канал не определён |
| В2 | Кто видит файлы, срок хранения, как удалить по просьбе? | заполняется в согласии (раздел 2) |
| В3 | Подтверждаются ли пороги FRR ≤ 5 % и cry-wolf ≤ 50 % и окно 30 дней, или их надо пересмотреть до замера? | в канон решение не внесено |
| В4 | Вариант А или Б (раздел 4)? | см. раздел 4 |

Рекомендации и выбор в этих вопросах пакет не делает: решает владелец.
