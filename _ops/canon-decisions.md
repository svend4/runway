# Runway — решения арбитра канона (v1.1)

> Рабочий документ проекта (не страница вики, без frontmatter). Дата: 2026-10-04. Автор: «Арбитр канона». Свод 133 замечаний писателей (`_ops/workflow2b-result.json`, поле `canon_issues`, нумерация 1-based) в **98 различных решений C-001…C-098**. Канон — [design-brief](design-brief.md); он обновлён до версии 1.1 по этим решениям (места помечены «(v1.1, C-NNN)», журнал — design-brief §13). **При расхождении страниц вики с этим файлом и design-brief v1.1 приоритет у них.** Числа сквозного примера G-001 не менялись: все изменения проверены независимым дневным расчётом (скрипт модели, ряды plan/worse, G-001-low/gap, вариант G-001-late) — ни один ключ `G-001.*` не затронут.

Принципы выбора: проще и тестируемее; согласовано с ADR и срезом v1 (design-brief §8); без скрытых допущений; один источник правды. Решение «принять» — предложение писателя вошло в канон без изменений; «изменить» — принято частично или иначе; «отклонить» — замечание не ведёт к правке канона. Колонка `needs_human = да` — настоящий продуктовый компромисс: решение принято, но владелец проекта должен его увидеть (раздел «Нужно решение владельца»).

Расшифровка расхождений, на которые опираются решения: (а) REQ-067 и design-brief §12 X8 задавали границу `stale` по-разному (`2·ttl` против `ttl + 120`) — C-023; (б) ALG-02 вызывал функции ALG-08 с устаревшими сигнатурами — C-034; (в) вердикт Q3 и `S_max` расходились при просадке `free` до даты покупки — C-015; (г) двойное округление в D-19 — C-028.

Решения приняты и внесены в канон; ниже — места, где выбор политический, а не технический. Формат: вопрос · выбрано · альтернатива · чем рискуем.

| C | Вопрос | Выбрано | Альтернатива | Чем рискуем |
|---|---|---|---|---|
| C-009 | Как складываются сдвиг даты в сценарии (`delay_income N`) и режим `worse` | Накопление: N + 14 дн.; `run_scenario` по умолчанию считается в `plan` | `max(N, 14)` для события, которое сценарий уже сдвинул (меньше двойного счёта) | Пользователь, считающий сценарий при `headline_mode = worse`, получает сдвиг больше названного; смягчено подписью и режимом `plan` по умолчанию |
| C-017 | Что делать с вердиктом, когда часть платежей за горизонтом | Вердикт считается по видимой части + неотделимая оговорка «не все платежи учтены: X за горизонтом» | Понижать вердикт (не выше `FRAGILE`) или выдавать «данных мало», пока горизонт не продлён | Ложное спокойствие по рассрочкам (RISK-02): 6-платёжная рассрочка G-001 даёт `OK` при 83 % платежей вне горизонта |
