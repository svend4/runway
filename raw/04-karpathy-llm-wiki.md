# 04 — Паттерн «LLM Wiki» (Андрей Карпати)

- **URL:** https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f
- **Дата доступа:** 2026-10-04
- **Форма досье:** конспект своими словами; gist — «файл идеи», предназначенный для передачи LLM-агенту, который сам достраивает детали.

## Суть

- Вместо RAG («на каждый вопрос заново искать фрагменты в сырых документах») LLM **постепенно строит и поддерживает постоянную вики** — структурированную, перелинкованную коллекцию markdown-файлов между человеком и сырыми источниками.
- Новый источник не просто индексируется: LLM читает его, вытягивает ключевое и **встраивает в существующие страницы**, помечая противоречия со старыми утверждениями. Знание «компилируется один раз» и поддерживается актуальным.
- Вики — «постоянно накапливающийся артефакт»: перекрёстные ссылки уже стоят, противоречия уже отмечены, синтез уже учитывает всё прочитанное.
- Человек курирует источники, направляет анализ, задаёт вопросы; LLM берёт рутину (резюме, перекрёстные ссылки, раскладка, учёт). Метафора: Obsidian — IDE, LLM — программист, вики — кодовая база.

## Три слоя

1. **Сырые источники** — неизменяемы; источник правды.
2. **Вики** — каталог markdown-файлов, которым целиком владеет LLM (резюме, сущности, понятия, сравнения, обзор, синтез).
3. **Схема** — документ (`CLAUDE.md`/`AGENTS.md`): структура, конвенции, рабочие процессы; эволюционирует совместно с человеком.

## Операции

- **Ingest** — прочитать источник, обсудить выводы, написать резюме, обновить индекс и затронутые страницы, дописать запись в лог (один источник может затронуть 10–15 страниц).
- **Query** — найти страницы, синтезировать ответ с цитированием; **ценные ответы возвращаются в вики** как новые страницы (таблица сравнения, анализ, Marp-слайды, график).
- **Lint** — проверка здоровья: противоречия, устаревшие утверждения, сироты, упомянутые-но-не-описанные понятия, пропущенные ссылки, пробелы данных (можно закрыть веб-поиском).

## Служебные файлы

- `index.md` — каталог по категориям: ссылка + одна строка + (дата/число источников). Обновляется при каждом ingest; на умеренном масштабе (~100 источников, сотни страниц) заменяет embedding-RAG.
- `log.md` — только добавление, префикс записи `## [YYYY-MM-DD] ingest | Название`, чтобы парсилось `grep`-ом.

## Необязательные инструменты (из gist)

- Локальный поиск по markdown (пример — qmd: BM25 + векторный + реранкинг, CLI и MCP) либо самодельный скрипт.
- Obsidian Web Clipper, локальные вложения, graph view, Marp (слайды из markdown), Dataview (запросы по frontmatter).
- Вики — это git-репозиторий markdown-файлов: история и ветки бесплатно.

## Почему работает (по автору)

Люди бросают вики из-за роста затрат на «бухгалтерию» (перекрёстные ссылки, актуальность, согласованность); LLM эти затраты снижает почти до нуля. Отсылка к Memex Вэнивара Буша (1945).

## Как применяется в этом проекте

См. [CLAUDE.md](../CLAUDE.md): те же три слоя, плюс `prototype/` (исполняемый код) и `tools/` (lint/index/log/search). Отступление от оригинала: `raw/` хранит конспекты источников, а не дословные копии (авторское право).
