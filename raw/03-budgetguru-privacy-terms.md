# 03 — Budget Guru: политика конфиденциальности и условия использования

- **URL:** https://budgetguru.es/en/privacy · https://budgetguru.es/en/terms (есть RU/ES версии)
- **Версия документов:** «Updated September 24, 2026» · **Дата доступа:** 2026-10-04
- **Форма досье:** конспект своими словами. Это наиболее информативный источник о реальной архитектуре продукта.

## Технические факты из политики

| Тема | Что сказано |
|---|---|
| Хранение | введённые вручную данные (счета, остатки, операции, статьи бюджета, рабочие часы, налоговые правила, инвойсы) хранятся в базе **Supabase** |
| Изоляция пользователей | **Row Level Security** — фильтрация по id пользователя внутри БД; административный доступ есть только у разработчика, используется для поддержки/по запросу |
| Вход | email + пароль через **Supabase Auth**, пароль хэшируется |
| AI-ассистент | вопрос + «снимок цифр» (остатки, план, ближайшие платежи — то, что приложение уже посчитало) отправляются на сервер; обрабатываются моделью **Claude через коммерческий API Anthropic** из серверной функции (ключ в браузер не попадает); история диалога на стороне сервиса не хранится дольше обработки запроса |
| Аналитика | **Vercel Web Analytics** (без cookies, агрегаты) |
| Обратная связь | текст и вложение сохраняются в БД; видит только разработчик через панель Supabase |
| Права пользователя | доступ, исправление, удаление, экспорт — **по запросу** (Telegram-бот поддержки или email); **кнопки «удалить аккаунт» нет**; удаление «обычно до 72 часов» |

## Факты из условий использования

- Статус: ранний доступ (публичная бета), «as is», без SLA; «не храните единственную копию важных цифр только здесь».
- «Не финансовый советник»: расчёт по введённым данным; ответы ассистента справочные, 100% точность прогноза не гарантируется; решения и ответственность — на пользователе.
- Запрещено: спам форм, автоматический парсинг/скрейпинг/нагрузка скриптами, обход защиты БД, реверс-инжиниринг; уязвимости можно сообщать.
- Изменения условий: о существенных (например, платный доступ) — личное уведомление.
- Инфраструктура третьих сторон: Supabase, Vercel (+ Anthropic API).

## Выводы для проектирования (вывод)

- Приватность Budget Guru — это «нет банковских API», а не «данные только у вас»: данные лежат на облачном Postgres, а часть цифр уходит в Anthropic API. Это нормально, но формулировку «финансы остаются только вашими» стоит читать с поправкой.
- Нет self-service экспорта/удаления — это пробел по GDPR-ожиданиям пользователей из ЕС (в тексте — «в разработке»).
- Архитектурный паттерн «детерминированный движок считает, LLM только озвучивает снимок» зафиксирован в политике явно — полезен как референс.

## Поправки (errata, проверка вторым проходом 2026-10-04)

Исходный конспект выше не менялся.

- **Каналы запросов** на копию/исправление/удаление данных: Telegram-бот поддержки, **форма обратной связи в приложении** и email (конспект выше форму пропустил).
- **Запрет реверс-инжиниринга** в Terms: «обойти защиту базы данных, реверс-инжинирить или искать уязвимости не для того, чтобы сообщить о них»; объект «реверс-инжинирить» грамматически не назван — нельзя утверждать ни «общий запрет», ни «запрета нет». Скрейпинг/нагрузка скриптами запрещены прямо.
- **Аналитика:** «по умолчанию без cookies» (оговорка «по умолчанию» в конспекте была опущена).
- **AI:** «история диалога не хранится» — про сам сервис; у провайдера (Anthropic) данные хранятся ограниченное время «только для мониторинга злоупотреблений», срок политикой не назван.
- **Изменения условий:** о существенных (например, платный доступ) обещано «написать отдельно» (канал не указан), а не «лично».
